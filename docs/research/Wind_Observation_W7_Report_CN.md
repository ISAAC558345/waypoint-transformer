# W7：空中切换可以在预测状态上提前选对，起飞前的先验还不行

基线是 d1c6fb5 的 W6.2。预报从每个决策的已提交动作出发，比较两种 60 秒航迹。A 把该动作再保持 60 秒。B 先把它执行到预测的 t+30，再调用现有高层，并执行守卫后的动作到 t+60。两机一起推进。验收只看航迹误差和这次预报的耗时。默认调度没有改。

预测窗口里保持决策当时的能耗信念，不吸收未来遥测，也不抽未来测量噪声。风只用无报文时的结构项，不含逆风均值。真实风、真实能耗系数、未来动作和未来位置只在预报存盘之后用来评分。副本没有改写实际轨迹。

场景在出结果前按冻结表的名字确定。已有案例是 `b3_loose`，种子 1103，真实能耗系数 `[1.0, 1.25]`。去掉它之后按场景名排序，第一个 tight 是 `b1_tight`，第一个 window 是 `b1_window`，种子都是 1101，真实系数都是 `[1.0, 1.0]`，差别只在电量。三组都用 W4 的逆风场。浮标和释放计划来自同一份冻结规格。`b1_tight` 与 `b1_window` 的动作不同，位置最大相差 1704.303 m，没有因为它们相近而继续换场景。`b1_tight` 按时交付 40000 bit，另外两组是 140000 bit。

主要数字来自当前仍在空中、并且未来 60 秒还在任务内的决策。30 秒端点误差在这些决策上两边都是 0。起飞前只有 0 秒，单独列出。落地之后的位置误差也是 0。

## 原案例的三处偏差

这三处是 W5.1 已经记录的 1 号机 60 秒位置偏差。30 秒偏差仍是 0。0 秒还在地面，30 秒和 120 秒已经在空中。

| 时刻 | 状态 | 实际下一动作 | A | B | B 选出的动作 |
| --- | --- | --- | ---: | ---: | --- |
| 0 秒 | 起飞前 | service:1 | 483.541 m | 445.961 m | service:0 |
| 30 秒 | 空中切换 | service:3 | 422.540 m | 0 | service:3 |
| 120 秒 | 空中切换 | return | 468.000 m | 0 | return |

0 秒的第一段 30 米误差是 0，守卫也没有改掉已提交动作。把 t=30 的真实世界留下，只把信念换回 0 秒的先验均值 1.1，高层就会选出 B 的错误动作。换上飞过第一段之后的信念，则选出实际动作。1 号机的信念均值从 1.1 变成 1.273，真实系数是 1.25。因此这处失败在未来信念，不在业务队列、动作选择器或守卫。

## 起飞前的退步

六个起飞前决策里，B 有三处仍然选错，其中两处比 A 更差。

`b1_window` 的 0 号机本来会继续 service:0，A 的 60 秒误差是 0。先验均值 1.1 在同一真实状态上选择返航，更新后的信念均值 0.979 才继续服务。`b1_window` 的 1 号机同样是先验选出 service:0，更新后的信念选出 service:3。两处都是未来信念。

落地后的位置误差两边都是 0。1680 秒有一拍从 return 变成 backhaul，飞机已经停住，所以 A 的动作正确率约为 0.98，位置不变。B 报出了这次 backhaul。

配置保持 `registered_before_run`，sha256 为 `49c252d44f671ee5206c188bf465686f0db3b9a948f6c3a5836ecc373b5fa43f`。

```powershell
$env:PYTHONPATH = "src"
py -3 -m unittest tests.test_wind_observation_w7
py -3 -m wt.active_model_identification.run_w7
```

原调度的交付、耗电或三处 60 秒偏差变了，会被归档检查抓住。预报步使用场景真实能耗系数，或改写决策当时的信念，会被隔离检查抓住。副本改写实际位置或信念，会被副本检查抓住。

配对结果在 `results/wind_observation_w7/w7_20261118/pairs.csv`，逐秒位置在 `tracks.csv`，分组汇总在 `scores.csv`。
