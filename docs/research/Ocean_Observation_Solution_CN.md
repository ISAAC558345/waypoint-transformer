# 无人机海洋观测系统实施方案

更新时间：2026-11-03。第一阶段研究问题：在相同飞行能量、通信资源和任务时间下，考虑观测冗余、信息送达时延和风相关飞行成本的调度，能否降低最终接收端在整个任务期间的海况估计误差。

执行顺序为：资源与接口核算、固定模型的观测闭环、信息价值调度、少量参数主动辨识、跨航次迁移。当前交付为设计方案；直接后继任务是配套的 [M0 核算指令](Ocean_Observation_M0_Instructions_CN.md)。后续训练和大规模评测的预算在获得 M0 与闭环基线结果后另行登记。

## 1 首版范围

| 项目 | 首版选择 | 目的 |
| --- | --- | --- |
| 规模 | 先用 2 架无人机、4 个浮标检查机制，再使用 6 架、12 个 | 提供可人工核对的小场景及与旧项目相近的规模 |
| 节点 | 自由漂流浮标、固定高度无人机、一个位置固定的岸站 | 固定最终融合端，控制环境复杂度 |
| 观测任务 | 估计有效波高场，附带评价指定阈值的超限概率 | 将信息价值落实到具体任务 |
| 数据产品 | 每个采样窗口生成一种带测量方差的有效波高观测包 | 先证明采集地点与送达时机的价值 |
| 决策 | 访问哪一个浮标、继续服务、前往回传位置、返航或等待 | 同时考虑获得信息与使信息可用 |
| 首版固定内容 | 采样窗口、产品定义、物理模型参数、低层控制规则 | 保证收益能够归因于高层调度 |
| 后续扩展 | 摘要与原始数据选择、采样控制、参数主动辨识、跨航次记忆 | 每次仅引入一种新的机制 |

保留无人机高低层分工和真实服务记账的思路。新任务采用独立环境和结果命名空间，不覆盖原来的 payload 实验。浮标之间不建立通信或数据转发链路，无人机之间也不新增无线中继。图网络的消息传递只用于计算。

## 2 数据与通信闭环

```mermaid
flowchart LR
  B[浮标生成观测包] -->|实际上传| U[无人机缓存]
  U -->|实际回传| S[岸站去重接收]
  S --> F[海况估计与不确定性]
  F --> P[候选价值与联合任务分配]
  P -->|有版本的任务消息实际送达| C[机载控制与可行性检查]
  C --> U
```

浮标上传和无人机回传是两个独立的传输过程。岸站只在完整观测包送达、校验通过且尚未融合时更新地图。部分接收、无人机缓存、重新发送和重复接收分别记账，不能产生重复任务收益。过时数据按预先登记的时序融合方法使用，或明确丢弃；不得把其采样时间改为送达时间。

采用集中调度、机载执行。岸站依据自己已收到的消息制定任务；无人机依据本机定位、风观测、电量和有效任务执行控制。无人机遥测、任务命令、确认和观测数据均占用链路时间和能量。不存在免费、即时、全知的控制通道。控制消息可优先发送，但优先级、长度与失败处理对所有策略相同；不得禁止同等大小的海况包走一条本来可用的链路，以人为制造信息瓶颈。

岸站的无人机状态、浮标位置和队列信息都带有最后接收时间。无人机完整收到有版本与生效时间的有效任务后按协议激活，并发送回执；岸站收到回执后才标为已确认，未收到时保留待确认状态，不能假定任务一定未执行。重复命令按版本去重。断链时无人机按本机最后激活且未过期的任务运行，超过期限或触及返航条件时执行固定回传或返航规则。

首版使用预先登记的时分接入和固定发射参数。两类链路分别核算距离、发射功率、天线、噪声、带宽、有效数据率、协议开销和失败概率。允许移动中通信；若特定硬件要求悬停，需要依据和单独配置。短数据包在一个运动步内按实际接触时长结算，不能一包固定消耗一个完整运动步。

## 3 先核算瓶颈

先计算采样业务量、完整数据包大小、上传时间、回传时间、访问航程和能量，再选择主实验工作区间。每个数值标明属于文献参数、设备规格、测量值还是合成假设。

原始数据量的核算式为通道数乘采样率乘量化位数乘窗口时长；实际发送的观测包长度则由序列化结果和协议开销确定。示例参数 3 通道、4 Hz、16 bit、1200 s 对应 230400 bit 原始记录，这只是核算示例，不是设备规格，也不是首版必须发送的大小。不得沿用旧环境的 1 Mbit block 作为每个海况摘要的虚构大小。

按三种情况报告资源负担：通信宽裕、通信与访问共同受限、回传间歇不可用。允许结论为飞行能量或访问时间主导；允许现有设定下所有信息都可及时取得。不能只保留对新策略有利的困难区间，也不能通过无依据地放大数据包或缩小带宽来产生收益。

浮标直接回传岸站的能力必须通过相同链路核算检查。若它可以低成本完成任务，就将直接回传加入对照，或收窄无人机方案的适用条件。M0 若发现无需无人机或无需信息选择，应如实停止该问题设定。

## 4 时间尺度与物理条件

以下只是 M0 的起始核算值，不构成已冻结实验参数：区域 2 km × 2 km、飞行高度 100 m、运动积分 1 s、高层常规重规划 30 s、观测窗口及产出间隔 1200 s、任务时长 1800 s。控制安全检查每个运动步进行，通信按步内接触时段结算。M0 必须检查这些数值与航速、机型功耗、实际通信能力和观测变化速度是否一致，再冻结正式参数。

采样窗口从任务开始前进行相同长度的暖启动，首包在 t=0 生成；后续包按真实完整窗口生成。所有方法共享暖启动场、初始岸站先验和预先存在的消息。暖启动成本单独记录并保持一致。第一阶段不学习采样率，也不引入电池充电和补给；离地前与落地后的任务状态必须明确定义。

无人机模型使用地速、空速和风速的关系 v_air = v_ground - w，在带机型参数的推进功率模型上积分焦耳，同时计算通信、计算以及起降成本。速度、加速度和转向约束要与积分步长一致。水平固定高度模型应写清适用范围，不能直接套用文献中的城市风场参数代表海上风场。

漂移使用海流、显式 Stokes 漂移与设备相关风漂移项，核对参考流速深度及系数含义，避免重复计入波浪作用。自由漂流浮标到达边界后继续漂移或离开任务域，不能为了保持节点可访问而无依据地反弹。

海况、漂移与链路扰动应具有时间相关性，并使用一致的背景环境。首版在观测产品层面生成可控合成有效波高场；不声称它复现了真实海浪波形。观测算子须处理时间窗口及窗口内浮标运动，不能把 20 分钟观测直接当作任意时刻、固定位置的瞬时真值。

ERA5 和 Copernicus 数据后续用于背景驱动，NOAA 漂流资料用于漂移验证；分别声明分辨率和可验证变量。再分析中的未来数据可驱动仿真真值，但不能作为当时可获得的预测送给策略。局地细节和未验证链路只能作为合成压力测试。

真值生成器与岸站估计器使用分离的状态和接口。匹配模型的实验只验证受控条件下的机制；泛化结论还要覆盖不同相关尺度、观测噪声和环境结构的模型失配，避免只在与估计器完全相同的生成模型中评价。

## 5 如何计算信息价值

岸站维护一个能输出均值和协方差的时空估计器，先选可核查的高斯过程或状态空间滤波基线，第一阶段固定其参数。策略输入包括已收观测、观测年龄、预测位置及其误差、地图不确定性、已知任务状态和能量估计；不包含未传输的测量值、异常真值或未来场。

主指标为固定任务区域内、整个任务期间的时间与空间加权 RMSE：先在每个评价时刻计算岸站预测与仿真真值的空间加权平方误差，再按真实持续时间平均，最后开方。空间权重、区域和评价时刻在比较前冻结。不能只在有数据到达时评价，也不能因浮标漂离而缩小评价区域。

高层排序使用的是预计送达后能够带来的误差下降。预测价值根据岸站已知信息计算，并考虑采样时间、预计送达时间、传输成功概率和数据的剩余有效性。仿真真实误差可以用于训练奖励与离线评价，不能泄漏到部署输入。

选第一架无人机的任务后，再计算其他任务相对于已选任务的边际收益。待执行任务以成功概率与预计送达时间参与联合价值预测；实际地图始终只由已收消息更新。这样可以区分“预计会收到”和“已经收到”，同时减少多架无人机重复采集相近信息。

低成本基线按预计有效信息收益与新增能量的关系进行顺序选择，并用联合条件更新处理冗余。滚动优化对若干次访问和回传联合评估。第一阶段候选覆盖所有物理可行的浮标以及回传、返航和等待，不用纯速率 top-k 作为共同入口；若随后需要剪枝，要单独测量价值候选的保留率。

如果进入强化学习阶段，训练奖励首先对应每段真实持续时间内的负地图误差，按固定尺度归一化；能量和安全通过预算及可行性约束处理。不要仅奖励后验方差降低，也不要依靠永久探索奖励宣布任务收益。状态、环境、观测估计器或低层控制变化后，旧权重需要独立验证。

## 6 约束与接口

任务可行性检查要求：当前剩余能量至少覆盖候选任务、保守回程和登记的余量。保守回程使用当时可获得的风预测和已声明的误差范围。此约束只在其模型和扰动范围内成立，极端模型失配单独统计。几何安全投影继续检查运动、边界和碰撞，不能替代回程能量检查。

| 新接口 | 主要记录或职责 |
| --- | --- |
| ObservationProduct | 产品 ID、浮标 ID、窗口起止、位置或轨迹摘要、估计值、方差、质量标志、编码长度 |
| NodeInbox | 每个节点实际收到的产品、遥测、命令版本与接收时间 |
| TransportLedger | 每段链路的字节、耗时、能耗、失败、部分接收、去重和最终交付 |
| ShoreBelief | 仅根据岸站收件箱更新的海况与位置估计 |
| CandidateBuilder | 可行浮标访问、回传、返航和等待任务；显式表示未知信息 |
| JointValuePlanner | 在冗余、延迟和资源约束下给候选组合评分 |
| FeasibilityGuard | 运动与回程能量检查、任务期限、固定断链行为 |
| Evaluator | 岸站全过程误差、风险概率质量、延迟、能量和事件记录 |

接口与节点数量从配置产生。首版采用固定的运动控制器验证动态目标拦截和约束，保留 MAPPO 为后续独立比较项。复用旧项目的框架和记账经验，不把旧模型在静态环境的收益解释为新任务收益。

## 7 对照和验收

| 对照 | 所回答的问题 |
| --- | --- |
| 固定巡检 | 改变访问顺序是否有效 |
| 速率优先 | 只重视通信能力会损失多少任务质量 |
| 最大不确定性 | 访问成本、时效和任务相关性是否必要 |
| 考虑成本与冗余的信息贪心 | 联合价值的简单规则是否已足够 |
| 同一估计器下的滚动优化 | 学习策略是否带来额外收益或更低决策开销 |
| 可行的浮标直传岸站 | 无人机在登记场景中是否必要 |

主要指标是全过程岸站地图 RMSE；次要指标为固定误报约束下的超限漏检与发现延迟、风险概率校准、最终有效交付、数据年龄、总能耗、返航失败、碰撞与约束事件。所有策略使用相同的物理预算、初始信息、传感器条件与估计模型；规划耗时和计算资源另行计量。

同一场景的外部风、海流、海况和条件噪声由独立于策略随机数消耗的生成器产生。观测可以依赖实际轨迹与采样时间，但不能因为某策略多调用一次函数而改变整场天气。统计单位是独立场景或航次，不是时间步、浮标或数据包。按场景配对分析；多训练种子不能当作新的独立海况。

训练、调参与最终测试按海域或时间块隔离，并记录相关长度及隔离间隔。先用开发数据估计方差，再登记最终样本量和训练预算；测试不参与候选、超参数或效果阈值选择。

第一阶段建议的实际意义门槛是：相对开发集预先选定的最强可部署非学习对照，平均配对 RMSE 相对下降至少 5%，且配对差的 95% 置信区间支持正向收益；这一数值是建议的验收阈值，不是效果预测。预算合规和任务安全条件同时满足，原始事件全部保留。最终阈值与安全数值容差在正式比较前登记。

若信息贪心已经达到相近效果，则确认价值调度机制有效，并保留较简单的方法。只有学习策略超越同信息条件的强对照，才能提出强化学习收益。小场景精确最优仅在确实穷尽和证明最优时使用该名称；有限前瞻搜索只作诊断。

## 8 后续研究的进入条件

第二阶段先选择一种待辨识参数。优先考虑风漂移系数，条件是已有足够的风、流与定位信息；先检查这些量能否区分参数作用。若数据只能识别总漂移残差，就将估计对象收窄为残差，不宣称分离了风、流和波浪原因。

主动辨识比较固定模型、自然反馈下的被动更新、成本匹配的随机验证、主动选择验证。评价额外动作后的后续任务收益，并计入全部验证成本。需要同时报告参数误差和任务误差；参数更准但任务未改善时，只能报告辨识收益。待第一种参数通过后，再单独讨论功耗或链路参数。

第三阶段只延续经过验证、具有适用条件的参数和误差分布。使用 A 海况、B 海况、再次 A 海况以及新的 C 海况评测，比较清空记忆、被动更新和保留记忆。位置与即时海况不作为永久知识；更新使用保留反馈检查，退化时能够恢复旧版本。在线参数学习与跨航次策略训练分别登记，避免两种变化混在一个实验中。
