# P3：保持正在服务的关联，只重分配到不了的 UAV

计划文本保留在提交 `6c2fea7`。本文件是该计划的结果。没有训练，没有改 FormalPlanner、奖励、动作或正式权重。保留测试 `322064–322079` 没有读取。P1 和 P2 的结果目录没有覆盖。

## Gate

`T45_ACTIVE_ASSIGNMENT_PRESERVED_INCONCLUSIVE`

16 个验证场景都在同一个 `t=45` 状态上完成了配对。候选数都是 13327，分支前状态哈希一致，账目最大误差 `1.82e-8` bit，安全违规率为 0。真正改变分配的场景只有 2 个，少于运行前写定的 3 个。16 个场景差值的 95% 区间也包含 0。

## 规则

只允许改那些当前有目标、距离大于 16 m、并且 `距离 - 16 m > 66 m` 的 UAV。已经在半径内的 UAV、3 步几何上仍可能进入的 UAV，以及空闲 UAV，目标都保持不变。空闲不作为更短距离。对照必须来自当时的合法候选池，不能改固定 UAV 的目标。选择时只看当前距离，不看 3 步后的 payload。

两臂都用冻结的 `phase6g_seed0.pt`，从同一快照和同一 last movement 出发，各走 3 步。`t=45` 的 scheme C 分配与 P1 逐场景一致。

## 证据

7 个场景没有待重分配的 UAV，分配不变。

另外 7 个场景各有 1 架 UAV 停在约 `95.73–99.61` m。固定其他 UAV 之后，合法候选里没有一个能把这架 UAV 放到 3 步几何可达的空闲浮标上。分配保持 scheme C，差值为 0。

只有 2 个场景换了分配，而且两架待重分配 UAV 的可达数都仍是 0。规则只是交换了它们已经够不着的两个浮标，总距离分别少了 `0.0065` m 和 `0.0337` m：

- `322059`：scheme C `7,0,1,11,8,9` 换成 `7,1,0,11,8,9`。UAV 1 和 UAV 2 交换浮标 0 与 1，交换后距离 `96.57` m 和 `90.54` m，3 步交付仍是 0。payload 从 `7505642.338` bit 变为 `7505627.221` bit，差值 `-15.116` bit。这 15 bit 出现在目标没变的半径内 UAV 上。
- `322061`：scheme C `0,11,7,1,10,9` 换成 `1,11,7,0,10,9`。UAV 0 和 UAV 3 交换浮标 0 与 1，交换后仍在 `95.02` m 和 `99.25` m，交付仍是 0。payload 从 `7382924.363` bit 变为 `7382912.929` bit，差值 `-11.434` bit。少掉的比特来自目标未改的 UAV 4。

这两个场景单独的区间是 `[-15.116, -11.434]` bit。绝对量和窗口里约 `7.5e6` bit 的交付相比，只是十余比特。没有一架原来到不了的 UAV 因此进入服务半径。

## 局限

在 `t=45`，近处浮标已经被要保持的 UAV 占用。剩余合法目标仍在 66 m 的闭合预算之外，所以这条规则没有可到达的替代目标。交换两个远浮标会稍微改变仍在服务的链路，但没有形成末窗增益。这不说明 48 步全程的高层策略已经改进，也不作为重训低层的依据。
