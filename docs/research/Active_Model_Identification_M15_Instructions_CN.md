## 1. 已有证据与本轮问题

先阅读本文件、[M1.4 报告](Active_Model_Identification_M14_Report_CN.md)、[M1.3 报告](Active_Model_Identification_M13_Report_CN.md)及相应实现。论文与分支设计已经是本研究的依据；沿用其物理模型、目标和主动辨识定义，不重新扩展问题。

M1.4 的来源统计为 76 条校准请求：9 条来自冲突修复，67 条来自单机评分首选。六个登记快照的分解恒等式成立，校准相对普通执行遥测没有正的净信息优势；这不意味着两者的单独信息溢价均为零。固定关闭后续校准的续策中，六个快照的 C+ 对 C−、E+ 对 E− 的交付量、能耗和净效用差均为零。

C+ 对合法非校准替代 E+ 的实际续跑中，六例交付量相同，四例增加耗能，另两例分别节约约 359 J 和 439 J。因此不能把校准动作整体禁用，也不能仅凭请求来自冲突修复就删除它。三条 single_score 快照的一步正差距全部来自前 30 秒运动成本，而 C/E 的终端业务均为 none；返航后落地停机的后续节能没有进入其比较。

代码中 `policies.terminal_value` 的 `best=0`，以及 `segment.describe` 的零下限，使“没有正收益的可准入业务”时终端值为 0。空中远离机坪与已经落地的状态因而可能具有相同终端值。本轮只检验这个局部近似是否造成可修正的性能损失；M1.4 原结果保留，不重新做来源归因或信息消融。

## 3. 实现一个明确的局部候选

增加显式终端模式，例如：

- `legacy`：旧行为，作为默认值；
- `return_tail_when_no_business`：本轮唯一新候选。

名称可以按现有配置风格调整，但报告、结果行和缓存必须能区分两种模式。

### 3.1 触发条件与估值边界

先按原算法确定终端业务和原值。存在原先被选中的正收益可准入业务时，保持其报价、选择和值不变。原值为 none/0 时，才用本轮返航尾成本代替该零值。

这里 none 指“旧算法没有选出正收益业务”，不等于没有任何合法业务：可能还有被零下限舍弃的负收益业务。本轮保持这部分既有业务选择逻辑，明确称为“旧 none 分支的局部成本修正”，不宣称完整最优终端估值。对触发状态记录是否存在这样的负收益合法业务及其最大值；不在同轮再加入业务包络重排因素。

新值为既有目标下的未来效用，保留负号：

`Q(a) = 已计入的本次 30 秒效用 + 后续返航尾效用`。

不能再用 `max(0, tail_value)` 抹掉尾成本，也不能把 none 直接映射成强制 RETURN。所有动作仍通过同一评分比较；校准的实际运动节能也应保留。

### 3.2 从正确的状态与时刻计费

对每个动作使用其自身执行 30 秒后的预测状态，按原执行器返回登记机坪、落地并关闭推进，再计到原 1800 s 截止时刻。尾成本包括原模型规定的推进、落地、辅助、地面负载及命令/遥测负载。已落地状态只计原有地面及通信负载，不能继续算飞行，也不能把其默认成完全零耗能。

沿用原终端使用的后验 95% 分位与原外层/噪声期望结构；不换成真参数或另一种风险口径。真实 θ 只用于独立执行和评价。备用电量是既有准入条件，不能当成已消耗能量加入奖励。

避免重复计费：前 30 秒及已付命令不再计入；正收益业务报价本来已经包含回传、返航和落地，本轮不再为其叠加一份返航费用。现有 `completion_quote(..., None, ...)` 含缓存回传，不能把它直接当成纯返航：返航尾过程按照 RETURN 的原物理语义处理已有缓存，不虚构交付收益。

任务时钟仍截至 1800 s。无法在剩余时间内落地、或在原能量约束下无法完成的状态，须按原模型记录实际截断成本与未完成状态，不能延长任务、假设成功返航或用免费成功状态填补；不另加惩罚项。原失败与保护语义保持不变。

### 3.3 一致计算与运行效率

`terminal_value`、分段终端描述、噪声期望和诊断输出使用同一新模式与同一尾成本定义；不要只改显示用参考函数而正式评分仍取零值。零值业务边界两侧由相同分段规则处理，尾项负值应进入实际积分。

优先复用原固定执行器、名义轨迹与 θ 线性能耗表示，缓存相同状态的返航路径和成本系数；剩余地面负载可解析计算。缓存键包含终端模式和影响报价的状态、剩余时钟等因素。不要对每个噪声节点重新逐秒模拟到任务结束，也不要通过扩搜索深度、扩大节点数或降低精度来解决本轮问题。

保持旧模式结果可重现。必要重构应局限相关模块，旧实验配置和原始结果均保持原样。

## 4. 先完成必要验证和六个快照核对

先登记实现模式、测试清单、容差、主试配置和预算，再运行。仅验证本轮新增机制：

1. 用一个明确的空中状态和一个已落地状态，对比分解成本与同一执行器的确定性 RETURN 参考；覆盖前 30 秒与尾段不重计、落地停推进、地面/通信仍计费、1800 s 截止。可共享固定样例，避免为同一事实堆叠测试。
2. 在原六个 M1.4 快照读取冻结状态：`b1_tight`、`b3_window`、`b1_loose`、`b1_window`、`b4_window`、`b2_loose`。旧模式与保存的 Q、原排序及分解在浮点容差内一致；只重算快照评分，不续跑旧航次。
3. 三条 single_score 快照重点列出 C 与 RETURN 的 R30、原终端、新尾值、新 Q、后验分位、落地时间和成本分量，检查尾值是否真正进入评分。三条 conflict_repair 快照作为控制；原正业务分支的终端值保持一致，修复算法不变。
4. 针对新尾项涉及的分段和模式缓存做一次局部数值核对：使用上述相关状态与更细的参考，仅检查新分支的 Q 与动作差。若临界差距无法由该局部误差界分辨，登记为未分辨，保留原 tie 规则；不自动启动大规模积分扫描。

不能把单个 Q 的误差直接当成两动作 Q 差的误差界；两边的误差需合并。也不要求新 Q 一定改选 RETURN 或校准请求必须清零，验证目标是成本一致和实际性能。

上述必要验证通过后进入主试；失败时修正本轮实现再复核受影响检查，保留记录，不运行主试来掩盖实现错误。

事前固定 corrected_ON 为主要候选，corrected_OFF 为配对对照。逐场景给出以下四组比较，不能事后逐场景拼接不同方法：

- corrected_OFF − legacy_OFF；

## 6. 事前性能判据

按时交付 bit 与净效用 J 分别比较，不能把两者写成能效比。浮点比较容差为 J 的绝对差 `1e-9`，按时比特按原离散交付精度比较（整数 bit 不容许减少）；原评分 tie 容差不作为性能回退容差。

局部修正得到性能支持，需要：

- corrected_ON 对同场景 legacy_ON、corrected_OFF 对同场景 legacy_OFF，两组各 12 对的交付量与净效用均不下降，并至少存在可复核的净效用改善；
- 原有物理完成与备用电量指标逐条披露，不能用物理状态恶化换取效用；
- 报告所有单场景差值，再给分档统计，不用均值掩盖回退。

若有任一回退，候选结论为“本轮未满足性能保留标准”，保留 opt-in 实现和完整负结果，不切换默认、不再修改权重/场景寻找通过。

即使以上通过，也必须如实判断 corrected_ON 对 legacy_OFF 是否有实际优势，以及 corrected_ON 对 corrected_OFF 是否仍存在损失。只超过旧 ON 不足以证明优于原先更好的 OFF。若 corrected_ON 低于 legacy_OFF 或 corrected_OFF，即使局部修正满足上述标准，corrected_ON 仍不获得主策略性能保留资格，不能描述为优于当前最佳执行方案。本轮最多支持终端估值改进；校准次数减少或效用增加本身不能证明主动信息收益成立，不追加信息消融以追求正结论。

本轮所有结果均维持显式候选身份，不自动替换旧默认模式。用户下一轮决定后续工作。
