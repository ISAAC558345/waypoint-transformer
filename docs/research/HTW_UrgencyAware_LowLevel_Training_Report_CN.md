# 紧急度低层训练报告

**Gate：`URGENCY_LOWLEVEL_INCONCLUSIVE`。**

组件记录：

- `URGENCY_LOWLEVEL_INPUT_SMOKE_PASS`
- `URGENCY_LOWLEVEL_TRAINING_COMPLETE`
- `URGENCY_LOWLEVEL_EVAL_COMPLETE`

L1 的闭环 payload 区间跨过 0。L2 提高了紧急服务，同时降低了 payload，而且三个 seed 的 payload 相差 5.74 Mbit。按训练前写好的保留规则，L2 记为 `TRADEOFF`，不替换冻结的 `phase6g_seed0.pt`。

## 实现

新代码在 `src/wt/benchmark_v2/phase6i_urgency_lowlevel/`。它复用 Stage A 的 `AdmissionAgeLedger`，任务由冻结 Scheme C 在合法满编池上给出。正式 observation、奖励函数、Planner、HGNN 和 `phase6g_seed0.pt` 没有改。

- L0 只评估，加载冻结 MAPPO-V2。
- L1 在原 8 维 task 后追加当前目标浮标的 `urgency` 和 `urgency_valid`，Actor 第一层为 36 维。Critic 保留原来的 188 维，再按 UAV 顺序追加 12 维，总宽 200。奖励调用原来的 `low_level_reward`。
- L2 使用同一套输入和同一个 300 次更新预算，只多一项 `lambda_urgency * sum(urgency * served_bits) / 1e6`。urgency 来自该步服务前的 ledger view。

热启动从 `phase6g_seed0.pt` 复制兼容权重。Actor 的两列新权重插在 task 块之后并置零，Critic 的 12 列新权重接在末尾并置零。因此额外特征一开始不改变动作均值。开发场景 321096 上，未训练的 L1 与 L0 闭环 payload 相差 0.056 bit。

预注册 seed 在看结果之前写入 protocol：`(0, 1, 2)`。`lambda_urgency = 1.0`。训练场景 321000 上，冻结 L0 的紧急服务 / payload 为 0.268，落在 0.1 到 10 之间，所以没有改权重。

## 测试与训练

`tests/test_urgency_lowlevel.py` 共 5 项通过：维度与零列热启动、目标浮标映射、无未来到达泄漏、L1/L2 奖励、账本守恒、checkpoint 读写和维度不匹配报错、Scheme C 单次更新 smoke。全库约 899 个测试没有重跑。

正式预算为 rollout 48、4 个环境、4 个 minibatch、4 个 epoch、学习率 3e-4、更新 300。六次训练都完成，没有非有限损失。每次训练约 2631–2675 秒。每次更新 16 次 Scheme C 调用，300 次更新共 4800 次。候选数始终是 13327，平均空闲槽为 0。

## 固定 15 步

每个开发场景先取一次 Scheme C 分配，再让 L0、L1、L2 从同一次 reset 执行这同一个 15 步 TaskOption。15 步总 payload 都是 `15000000.000` bit，配对差在 1 bit 以内，32 个场景全部持平。首次进入服务半径仍是第 0 步。前 15 步最老等待约 10 步，urgency 达不到 0.5，所以高紧急首次服务步为 -1。0.75 分位在这段里经常是 0，因此该分位服务量等于总 payload，不能当成紧急优先的证据。

同一总 payload 下，紧急服务仍有差别：

- L1−L0 紧急服务 `+35361.958` bit，区间 `[30012.857, 40722.085]`，32/0/0。
- L2−L0 紧急服务 `+41761.996` bit，区间 `[31640.091, 51710.241]`，28/4/0。
- L2−L1 紧急服务的区间跨过 0。
- L1−L0 路径 `+6.920` m，L2−L0 路径 `+6.463` m，正服务步都略增。安全违例步的区间跨过 0。

新输入在共享任务的 15 步里改变了服务构成。闭环里 Scheme C 会按各自轨迹重新选任务，这个 15 步差别没有变成稳定的 payload 提升。

## 保留决定

训练前的规则是：L2 相对 L1 的紧急服务区间下界大于 0，并且 payload 区间上界不低于 -1 bit，才保留 L2。现在紧急服务下界大于 0，payload 上界为 `-996333.359` bit。结果是 `TRADEOFF`。L2 不进入后续默认低层。L0 继续使用冻结 MAPPO。

逐步日志：`closed_loop_step_rows.csv` 为 36,236,157 字节，`fixed_hold_step_rows.csv` 为 10,416,301 字节。哈希只写在每个时间步的 UAV 0 行。图在 `results/phase6i_urgency_lowlevel/figures/l0_l1_l2_closed_loop.png`。

## 下一步

低层先停在冻结的 `phase6g_seed0.pt`。L2 的紧急服务增益和 payload 损失绑在一起，而且 seed 1 与另外两个 seed 方向不同，现在没有一个可以替换正式低层的候选。高层 HGNN 的紧急度改造留到下一条单独指令；本阶段不启动。
