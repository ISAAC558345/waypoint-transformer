## 1. 直接结论

两类单点干预都改变了真实 48 步 payload，但方向不一致，不能把 D3 的闭环损失归因到单独一个决策时刻。

t=0 只换一次 tie-break、之后恢复 Scheme C 时，四个场景的 episode payload 差是 +3,015,796.73、−2,879,057.93、+3,174,870.86、+4,699,191.22 bit。三升一降，均值 +2,002,700.22 bit，中位数 +3,095,333.80 bit。

t=30 只换一次 tie-break、其余决策用 Scheme C 时，payload 差是 −3,637,488.73、−2,365,824.38、−961,567.60、+3,013,463.30 bit。三降一升，均值 −987,854.35 bit，中位数 −1,663,695.99 bit。

每次被选中的候选，相对 128 个候选里的最大标签 payload，差距都不超过 1 bit。这个标签并列不能推出 48 步真实 payload 相等。t=0 的 15 步真实转移仍然和标签一样只有浮点尘埃差，兆比特级差距出现在 t=15 之后的 Scheme C 重规划。t=30 的 15 步真实转移本身就已经离开 1 bit，标签差仍然是尘埃。

规则仍是 oracle-label。它读取冻结 MAPPO-V2 的 rollout 标签，不是 HGNN 策略，也不能迁移到正式 Scheme C。`lambda_H` 与 `delta_payload_max` 仍未定。四个场景只做逐场景配对描述，不宣称显著性或泛化。

## 2. 实验与预算

场景是 registry 中 `highlevel_v2_train` 的前四个，并经过 `assert_allowed(split="train")`：322000–322003。没有读取 validation 或 reserved test。

三臂从同一个 reset seed 出发：

- `scheme_c`：t=0、15、30、45 都调用正式 `FormalPlanner("scheme_c").select_assignment`。
- `intervention_0`：只在 t=0 执行 D3 的 payload-first + urgency tie-break，t=15、30、45 恢复 Scheme C。
- `intervention_30`：t=0、15、45 用 Scheme C，只在该臂自己的 t=30 状态上重新抽样并执行 tie-break。

Scheme C 是确定性的，所以每个场景只跑一条控制轨迹，再与两个干预配对。实际是 12 条 48 步 episode，在 16 条上限之内。干预前的状态哈希对照说明 t=30 之前干预臂与控制臂重合，没有少做对比。

低层是冻结 MAPPO-V2 seed 0 的确定性均值，环境与 SafetyProjector 与正式闭环相同。正式 Planner 源文件没有修改。诊断 runner 只在已加载的 scorer 实例上记住本次选中标量，用来记录 Scheme C score。记录的 score 属于正式选择，不是 tie-break assignment 的分数。

t=0 的四个 tie-break 直接复用 D3 决策日志。现场状态哈希与 D3 的 `stored_j15` 行一致，没有重打这 128 个标签。t=30 的状态是 Scheme C 轨迹，不是 D3 的分叉状态，因此四个场景都在现场重新生成 128 个候选并打 15 步标签。候选列表在 urgent rollout 之前写入 `selected_candidates.csv`，共 512 行。抽样种子仍是 603。t=30 的状态对不上冻结 shard，抽样分来自当前 G1 加性速率；规则本身仍只看 MAPPO 标签。这 128 个候选不是 13,327 的全池前沿。

运行前先做了两次 Scheme C 全池选择：0.358 秒和 0.316 秒。按 2 次探测加 48 次正式选择，再加标签与诊断余量，估计总时间 115.9 秒。第一个场景实际 11.58 秒，外推四场景约 47.0 秒，低于 20 分钟停止线，因此跑完四个场景。

另外在干预瞬间做了两种 15 步诊断，诊断不参与选候选：

1. D3 兼容的零到达标签 rollout，只用来确认标签 payload 差不超过 1 bit。
2. 真实转移配对：同一快照恢复出两份独立副本，保留 `arrivals_at`，一份执行 payload-first，一份执行 tie-break。`arrivals_at` 只由时刻决定，两份副本的外生到达量差为 0。`capture_state` 不复制 reset RNG；该 RNG 只在 reset 时抖动 UAV 初始 y，不参与之后的到达。诊断的上一步动作按标签打分器置零，这样 t=0 与现场一致；t=30 的现场闭环仍携带上一步动作，所以 t=30 的诊断幅度不能当成现场前 15 步的精确复刻。

## 3. 完整性

12 条 episode 都是 `status=ok`、`final_t=48`。逐步日志 576 行，决策日志 48 行。账本与 `q_bits`、payload 与 served、队列守恒的最大误差都在 1 bit 内。8 个干预决策的标签 payload 差都在 1 bit 内，候选数都是 128，两份真实副本的外生到达都配上了。

`intervention_0` 的 t=0 状态哈希等于控制臂，也等于 D3。`intervention_30` 在 t=0、15、30 的状态哈希等于控制臂，且 t=0 和 t=15 的执行 assignment 与控制臂相同。八个干预相对同状态的 Scheme C assignment 都实际发生了改变。

D0 标签、D1 标签、D2 summary、D3 summary、D3 决策日志和正式 `planner.py` 的 SHA-256 在运行前后一致。冻结 MAPPO、Scheme C、epoch 6 和 adapter config 的哈希与既有登记值一致。没有训练 HGNN，没有改奖励、动作或 checkpoint。

## 6. 后续高层、SINR 与服务

t=0 干预之后，四个场景的 t=15 Scheme C 仍然选择浮标 `{6,7,8,9,10,11}`，但 UAV 对应关系与控制臂不同。322000 和 322001、322003 在 t=30 也还是这一组浮标的另一种匹配。322002 在 t=30 已经换成另一组：控制臂仍是 `{6..11}`，干预臂是 `{0,6,7,8,9,11}`。到 t=45，四个场景的浮标集合至少有一个与控制臂不同，只有 322000 的 t=45 集合仍相同，是 `{0,6,7,9,10,11}` 的不同匹配。322000 的集合一直相同，48 步 payload 仍然相差 +3,015,796.73 bit。同一组浮标的不同 UAV 匹配就足以留下兆比特差距。

t=30 干预的当步匹配仍是 `{6..11}`。随后 t=45 的 Scheme C 在 322000、322001、322002 上换成了不同浮标集合；322003 的 t=45 集合仍是 `{6..11}`，只是匹配不同，episode payload 仍相差 +3,013,463.30 bit。

六个 UAV 在所有臂的第 0 步都已进入服务半径，首次进入时刻没有分开。正服务步数只在 t=0 干预上有变化：相对控制臂为 +1、+2、+2、−1。t=30 干预的正服务步数差全是 0，payload 仍有兆比特变化，变的是每步服务量，不是“有没有服务”的步数。

全 episode 平均 SINR 差，t=0 为 +0.004869、−0.116935、+0.073997、+0.021345；t=30 为 −0.017824、−0.018838、+0.004713、+0.013244。t=30 的前 30 步与控制臂完全相同，会把差稀释。只对干预及之后的步取平均时，t=30 的 SINR 差是 −0.047531、−0.050235、+0.012569、+0.035317，干扰差是 +0.031996、+0.028255、+0.014411、−0.012929。SINR 和干扰都没有统一方向。SafetyProjector 触发步数和安全距离违反步数也没有统一变好。

路径长度和最老等待步数同样分叉：t=0 的路径差为 +19.66、+3.79、+31.37、−27.59 m，最老等待差为 −6、+2、0、+9 步。这些量随匹配几何变化，不能单独解释 payload 方向。

## 7. 和预注册解释的对照

“t=0 负收益、t=30 几乎不变”不成立。t=0 有三个场景 payload 上升，t=30 有三个场景下降，而且 t=30 的幅度是兆比特，不是可忽略的尘埃。

“只有 t=30 稳定为负”也不成立。322003 在 t=30 上升约 3.01 Mbit。

两类干预都没有一致方向。t=30 的差距里，真实到达相对零到达标签的贡献是清楚的：标签差在 1 bit 内，保留到达的 15 步差已经是兆比特。t=0 的 15 步真实差却不是这个机制，那里的 episode 差距来自后续 Scheme C 对同一批浮标的重新匹配。两种机制同时存在，符号还随场景变化，所以不能收成一个可执行规则。

D3 里 tie-break 全程替换 payload-first，平均 payload 约 −2.25 Mbit。本阶段的对照臂是 Scheme C，不是 D3 的 payload-first，数值不能直接相减。能够接上的结论只有一条：1 bit 的零到达标签并列，既不能推出 15 步真实 payload 并列，也不能推出 48 步 Scheme C 闭环 payload 并列。
