# M0B 任务说明

本说明在派生计算之前冻结。几何、包长、风速、能量参数和 M0A 的 18 行结果都只作输入。本提交不写入派生数字。

## 要回答的问题

M0A 里，单站 B 只有一个接收点，移动方案 C 的两架飞机各重复一个接收点。C 优于单站 B 的结果，本身还不能解释成动态调度收益。B2 用同样的飞机数量和同样的接收点，把“多站覆盖”和“飞行中改派”分开。

## B2

六个上下文保持原样：三种几何、两种风、四枚浮标、八个产品、两架飞机、岸站和机场不变。

B2 最多两架飞机。每架有任务的飞机只使用一个固定接收点。这个点、两个产品窗口的进入和离开时刻、起飞和降落，以及命令、确认、浮标载荷、回传的发送顺序，都取自该上下文里原移动方案分给这架飞机的任务。两个窗口之间不要求连续悬停；飞机降落之后可以再次起飞。没有分到访问的飞机留在地面。

因此 B2 的任务书和原移动方案 C 是同一份任务。若后面的资源时序也一致，比较结果标注「策略等价、复用已算结果」，不把这次复用计成新的独立实验。

## 身份

保存的飞行记录里，`_fly` 把两架飞机都写成 0。派生视图另记三列：原列表下标、记录中的 `uav` 值、实际任务分配的飞机编号。编号来自几何访问里已经冻结的分配：质心 x 大于或等于 0 的集群给飞机 0，其余给飞机 1。能量仍放在原来的列表位置上，该位置与实际编号一致。每架飞机的能量和单机限额比较。系统总能量单独列出，不拿去和单机限额比较。原 `schedule.json` 不改。

## 通信时序

本包的 B2 和 C 使用同一条简化规则：岸站方向一条半双工信道，同一时刻只容纳一个发射。

稳定顺序是：产品生成时刻，飞机编号，浮标编号，阶段。命令和确认的浮标编号记为 -1，所以排在该飞机的浮标包之前。阶段顺序是命令、确认、载荷、回传。

已有的 `MAC_GUARD_S` 继续作为相邻发射之间的间隔。本包不另设保护时间。后一个发射只在它的原计划区间会占用尚未释放的信道时才推迟；已经错开的间隔保持不变。遥测仍只计入能量，不插入交付时钟。

直接链路和单站方案里没有两架飞机同时发射。这条规则只作用于实际重叠的岸站方向发射。几何、航速、接收点和原 18 行都不因这条规则重算。
