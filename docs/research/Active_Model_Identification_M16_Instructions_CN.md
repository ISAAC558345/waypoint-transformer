# M1.6 可执行候选与浮标分配一致性修正

日期：2026-11-14。
执行分支：`research/ocean-observation-isolated`。
审查基点：`62d9c383617f023a19d323f4d941c3203ebf90f7`。
本轮完成一个显式开启的候选选择修正、必要验证、固定配对评估和中文报告，并推送本研究分支。

## 1 已有结果与本轮问题

先读 [M1.5 报告](Active_Model_Identification_M15_Report_CN.md)及本文件。M1.5 的 24 条新航次中，11 个场景在同校准开关下保持交付量并节能，`b3_loose` 的 ON/OFF 两条均比 M1.3 少 20000 bit，净效用分别下降约 1.931783280 和 1.936221054。M1.5 未满足性能保留标准，保留全部原始结果。

本次审查复算了 48 行比较表，效用差与原奖励公式的最大残差约为 1.4e-15。`b3_loose` 两种开关在 180 s 前的请求、执行、位置、电量及后验与各自 M1.3 日志逐行一致。180 s 时发生以下变化：

- 原 M1.3 请求为 UAV0 service:0、UAV1 backhaul；
- M1.5 两机评分首选均为 service:0，冲突修复让绝对 Q 较低的 UAV0 改为 RETURN；
- 留给 UAV1 的 service:0 在实际执行中变为 RETURN，后面多个区间重复出现；
- 缺失的是浮标 0 的两个 10000 bit 包。浮标 3 的缓存仍在任务末交付，不能把这 20000 bit 错归为浮标 3 丢包。

代码存在一条可证的机制链：`policies.candidates` 保留所有尚有包的 service 标签，`segment.roll_action` 经过原守卫后已记录实际动作，但 `score_segment` 把 Q 绑定回原请求标签，`_repair` 只比较 service 标签和绝对 Q。一个即将被原准入器改成 RETURN 的 service 标签因而可能仍占据浮标，迫使另一架退让。这些段落在 M1.5 中没有修改。

本轮先复核 180 s 的替代发生在期初还是区间中途，再修正期初已经不可执行的候选标签。M1.5 的计账与积分验证已经完成，本轮不把性能损失预判为尾成本错误。

M1.5 的 ON 总共请求 9 次校准，9 次均由冲突修复改派，没有校准作为单机评分首选。本轮事前登记“保留普通业务遥测、关闭专门校准”的修正 OFF 为主要候选，修正 ON 为对照。正常任务的能耗辨识继续工作，ON/OFF 差值只说明行为效果，不据此宣称信息价值。

## 2 先复核两个共同前置快照

只恢复 `b3_loose` 的 ON、OFF 各自 180 s 决策前完整状态。优先读取已保存状态；若原文件没有快照，按各自冻结的前六个请求区间和种子重放，不运行规划搜索。保存完整物理状态、缓存包、交付记录、信道时钟、后验和噪声索引，并与已保存前缀核对。ON 与 OFF 的状态分别使用，不能互换。

在两份快照上按原后验 95% 分位调用既有 `apply_option_guard`、`action_allowed` 和必要的期初 `_return_guard`，记录每架 service:0 的完整任务报价、可用电量、备用量、准入结论及期初有效动作。随后用原执行器核对一个区间的请求、期初有效动作、区间中途替代时刻和最终执行动作。

仅从区间末 executed=RETURN 不能断定期初已不可服务。若复核显示实际是中途替代，记录这一结论并停止本轮候选实现与主试，提交诊断报告；不为满足预设根因扩大修改。

同时保存旧 legacy 与 M1.5 尾模式在各自同一状态上的完整候选表、原 pick、冲突修复和实际执行阶段。对比请求标签与被估值的物理动作，说明尾项改变了哪些候选次序。选中动作的 `tail_triggered=0` 只是原探针记录，不证明所有候选、所有噪声节点都未受尾项影响。

## 3 唯一修改因素

确认期初 service 被原准入器改成 RETURN 后，新增显式选择模式，例如 `initial_guard_consistent`，旧选择模式仍为默认。本轮候选使用 M1.5 的 `return_tail_when_no_business` 终端与这个新选择模式。终端公式、冲突强弱规则、tie 容差和动作优先级沿用原实现。

在正式评分入口生成候选后、展开和冲突分配前，用当前状态和当前信念调用同一套既有期初守卫：

1. 将候选映射为该时刻原执行器实际会接受的动作。会在期初被改成 RETURN 的 service 标签不再拥有 service 目标。
2. 对相同有效动作去重。RETURN 使用正式 RETURN 候选自身的评分，不把被转换的 service 的标签、分数或业务收益移植给 RETURN，不重复积分。
3. 在这些有效候选上使用原评分、pick 和 `_repair`。两架都能执行同一 service 时，原绝对 Q 冲突规则和 tie 规则继续生效。本轮不改为机会成本分配或联合搜索。
4. 保留最终执行器的原检查。当前可准入、但未来区间内可能触发返航的动作继续按原模型预测和计账，本轮只规范期初替代。

实现必须接入 `score_actions/select_lookahead` 的正常调用链，使主试实际使用修正，不能只在诊断脚本中改动作。候选映射只读当前可观测状态及后验，不读取真 θ、未来观测或已知试验结果，也不按场景 ID、种子、时刻或浮标编号写例外。

报价与物理展开优先复用现有缓存。若缓存候选表或最终选择，缓存键应区分新旧选择模式；纯物理报价可继续共享。减少重复候选展开，保持原积分精度，不增加规划深度。

## 4 必要测试与先行评估

修改前在运行清单中列出“修改点、可能影响、必要验证”。用户只做必要测试的要求优先于旧通用全库测试规则。测试仅覆盖新增选择语义和受影响入口：

- 一架对某 service 期初不准入、另一架可准入时，被转换的标签不占用服务目标，实际请求与正式评分的动作对应；
- 两架均可执行同一 service 时，原冲突强弱与 tie 规则得到相同结果。映射成同一 RETURN 的别名只评分一次；
- 在上述两份冻结快照，旧选择模式能重现已有表和联合请求，新模式经正常入口得到的有效动作与原期初执行器一致。

成本分解、分段积分、后验更新和原物理模型的全套验证不重做。仅当本轮实际改动触及某项既有行为时，复核相应测试，不运行无关全库或安全专项。

先从正常入口运行 `b3_loose` 的新 OFF、ON 两条完整航次，记录原、新候选映射和首次分歧。若新模式 180 s 前仍与各自冻结前缀完整一致，这两条航次同时作为同状态反事实续跑，不再额外运行。若提前产生分歧，至多增加两条从冻结 180 s 快照起的新选择模式续跑，用于隔离该时刻机制；原 M1.5 的对照后缀直接读取，不重跑。

反事实保留原方法对应的后续策略、种子及绝对时间噪声索引，仅改变本轮候选选择模式。比较浮标 0 两包的采集、持有、回传时刻和最终去向，以及总交付量、净效用和能耗。不能把前置动作不同的完整航次差值直接归因为 180 s 单次分配。

只有实现验证通过，且主要候选新 OFF 在 `b3_loose` 对 M1.3 OFF 和 M1.5 OFF 均保持交付量与净效用，才补运行其余 11 场景的 22 条新航次。ON 作为对照如实披露，其回退不替代对主要 OFF 候选的判定。若主要 OFF 先行结果仍回退，保留结果并结束本轮，不通过继续改规则、加场景或调整预算寻找通过。

## 5 固定配对主试与保留标准

主试仍为原 `4 base × 3 电池档 × ON/OFF = 24` 条，包含已完成的两条先行航次。保持 2 UAV、4 静态浮标、1800 s、30 s 决策、1 s 步进，使用相同真实参数、种子、电池、先验、遥测、奖励、备用量和风险分位。分段积分沿用 15 点外层、7 点内层。

旧 M1.3 和 M1.5 的各 24 条核心航次均作为冻结对照直接读取，登记来源提交及文件 SHA256。每个场景固定报告：

- 新 OFF − M1.5 OFF，用来判断选择修正本身的效果；
- 新 ON − M1.5 ON；
- 新 OFF − M1.3 OFF，用来判断被动主候选是否保持已有性能；
- 新 ON − M1.3 ON；
- 新 ON − 新 OFF，用来报告专门校准开关的行为差异。

按时 bit 与净效用分别比较。整数 bit 不容许减少，净效用绝对浮点容差为 1e-9；评分 tie 容差不作为性能回退容差。全 12 场景的新 OFF 对 M1.3 OFF 及 M1.5 OFF 均无回退，且有可复核的净效用改善时，才判“被动候选在本组登记场景得到性能支持”。新 ON 同样逐场景评价，不允许按场景拼接 ON/OFF 成赢家。

分别列出 not_returned、not_landed、energy_exhausted、return_failures、below_reserve，主要 OFF 的原完成与备用量指标不能变差。ON 的计数独立披露并判定其自身资格，不作为 OFF 的保留门槛。先报告全部逐场景差值，再统计分档结果。即使全部通过，本轮也维持显式候选身份，默认模式后续由用户决定。

同时报告候选展开量和决策耗时，说明去重与报价复用的计算效果。沿用可比的展开数，机器或计时口径不同的旧耗时不能直接宣称加速。性能改善必须来自调度修正，不能靠减少任务或评价时长、降低精度、增加电池或改权重取得。

## 6 预算与交付

快照与局部评分诊断上限 6000 次 30 s 展开，24 条新主试合计上限 250000 次。仅在前置状态提前分歧时，额外同状态续跑最多两条，共上限 24000 次。分别记录评分展开、缓存命中、准入报价、尾报价逐秒步数、执行步数和耗时。触顶保存已完成结果及原因，不自动扩预算。

本轮不追加校准信息消融，不训练，不新增风浪、共享环境参数或无线 ISAC 模块。此前关于通感的讨论说明正常任务可以携带环境观测，当前仓库仍是静风下的个体能耗辨识模型；这次选择一致性实验不能宣称已验证风浪感知或共享环境收益。
