## 3. 逐状态 Pareto

支配规则：候选 a 支配 b，当 a 的 payload 和紧急服务都不比 b 差，并且至少一项高出 1 bit 以上。Payload-first 在并列组内取紧急服务最高者，再取较小的候选 ID。Urgent-first 在紧急服务并列组内取 payload 最高者。

| 范围 | 状态数 | 抽样 Pareto 均值 | 最佳 payload 并列数均值 | 成对 payload 并列比例 | 紧急最优落在并列内 | 实质损失状态 | 并列内平均紧急增益 (bit) | 实质 top-1 regret 均值 (bit) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| D0 t=0 | 4 | 1.00 | 36.50 | 0.1569 | 4/4 | 0 | 258,939.85 | 0 |
| D0 t=15 | 4 | 1.75 | 8.00 | 0.1396 | 2/4 | 2 | 70,596.43 | -41,502.63 |
| D0 t=30 | 4 | 1.00 | 34.75 | 0.0873 | 4/4 | 0 | 323,096.89 | 0 |
| D1 t=30 | 12 | 1.08 | 36.92 | 0.0975 | 11/12 | 1 | 533,979.13 | -133,418.33 |
| 全部 t=30 | 16 | 1.06 | 36.38 | 0.0949 | 15/16 | 1 | 481,258.57 | -100,063.75 |

成对并列比例是 128 个候选里 payload 差不超过 1 bit 的候选对占比。最佳 payload 并列数是与该状态最高 payload 相差不超过 1 bit 的候选个数。t=30 大约有 37/128 个候选和最高 payload 并列，但全部候选对里只有约 9.5% 属于这种并列。

24 个状态里有 21 个的抽样紧急最优已经在 payload 并列组内。抽样前沿在这些状态上只有 1 个非支配候选：它同时是 payload 并列组里的紧急服务最优。其余候选即使互相交换 payload 和紧急服务，也被这个点支配。

实质损失只出现在三个状态：

| 状态 | Payload-first | Urgent-first | 实质 payload 损失 (bit) | 相对 Payload-first 的紧急增益 (bit) | 首次出现实质损失的 lambda |
| --- | ---: | ---: | ---: | ---: | ---: |
| 322000 t=15 | 5337 | 5317 | 99,002.36 | 81,585.70 | 1.213 |
| 322002 t=15 | 9948 | 9941 | 67,008.16 | 7,743.48 | 8.653 |
| 322015 t=30 | 4692 | 8311 | 1,601,019.99 | 151,821.58 | 10.545 |

322000 t=15 还有一个抽样非支配点 6465。它牺牲 93,388.79 bit payload，换到 69,892.49 bit 紧急服务。它到下一个点的边际交换率下降，所以加权和路径不会选它。322002 和 322015 的抽样前沿只有两个点。

三个状态的局部前沿见 `results/phase6i_urgency_utility_rule/pareto_material_states.png`。图的横轴是相对最高 payload 的 regret，纵轴是相对 Payload-first 的紧急服务增益；远离前沿的候选被裁到窗口外。28 行完整抽样前沿在 `pareto_rows.csv`。

## 4. 并列和真正的 payload 损失

D1 场景 322015 的最高 payload 是 20,809,504.88 bit。以下三个候选的 payload 完全相同：

| 候选 | 角色 | 紧急服务 (bit) | 分配 |
| --- | --- | ---: | --- |
| 6292 | D1 登记的 payload 第一名 | 6,493,975.744 | `7\|6\|11\|8\|10\|9` |
| 4658 | 并列组中的最小候选 ID | 6,601,368.431 | `6\|7\|8\|11\|10\|9` |
| 4692 | Payload-first，紧急服务 tie-break | 7,193,623.613 | `6\|7\|9\|11\|10\|8` |

从 6292 改到 4692，payload 不变，紧急服务增加 699,647.87 bit。从 4658 改到 4692，紧急服务增加 592,255.18 bit。这两种改法都只是并列组内的选择，不是 payload 损失。

8311 的 payload 是 19,208,484.89 bit，分配是 `8|10|-1|7|6|11`。相对 4692，它再增加 151,821.58 bit 紧急服务，但要付出 1,601,019.99 bit payload。这才是实质损失。D1 公布的 -1,601,019.99 bit 描述的是这一步，不是 6292 和 4692 之间的差别。

其余 11 个 D1 状态里，紧急服务 tie-break 选出的候选就是 D1 的紧急服务第一名，而且它与 D1 的 payload 第一名处于 1 bit 并列。D1 的 12/12 top-1 ID 变化，在 1 bit 规则下只剩 322015 一处实质损失。D1 的平均实质 regret 仍是 -133,418.33 bit，因为 322015 保留在正式数字里。

t=0 的四个状态也都能在并列组内拿到紧急服务增益，平均 258,939.85 bit，没有实质 payload 损失。t=15 只有 322003 有这种免费增益；322000 和 322002 的最高 payload 在抽样里是单独一个候选，没有可以免费利用的并列。

## 5. lambda 临界点

交叉点使用同一套归一化单位：

`lambda_cross = (payload_i - payload_j) / (urgent_j - urgent_i)`

bit 差的比值和 term 差的比值相同。只保留紧急服务严格增加、并且 payload 代价为正的有限非负斜率。每个状态的 top-1 路径从 Payload-first 开始，沿抽样前沿的凸链走到紧急服务更高的点。成对交叉点很多，但被支配的交叉点不会改变 top-1。

D1 每个状态平均有 493.6 个正的成对交换，最多 667 个；D0 的 t=30 最多 861 个。支配之后，24 个状态里有 21 个的凸链只有一段，lambda 从 0 到无穷大都停在 Payload-first。真正改变 top-1 的实质临界值只有三个：

- 322000 t=15：lambda 达到 1.213 后，top-1 从 5337 变为 5317。
- 322002 t=15：lambda 达到 8.653 后，top-1 从 9948 变为 9941。这一步用 67,008 bit payload 只换 7,743 bit 紧急服务。
- 322015 t=30：lambda 达到 10.545 后，top-1 从 4692 变为 8311。

`lambda_breakpoints.png` 只画了这三个状态。其余 21 个状态没有有限的实质临界值。临界值在 t=15 和 t=30 之间差了一个数量级，t=0 则完全没有实质切换。因此不存在一个可以同时用于三个决策时刻的全局 `lambda_H`。候选 ID 本来就不能跨场景比较；跨状态稳定的是选择类别，不是某一个 ID。

D1 在 lambda 从 0 开始时，12/12 个状态的 Payload-first 分配都不同于“只按最小候选 ID 取 payload 并列”的分配，但 payload 没有实质变化。沿 lambda 继续增大时，12 个状态里只有 322015 的 top-1 分配会再改变一次。

## 6. 三种规则

### Payload-first

先取 payload 最大的候选，紧急服务只在 1 bit 并列组内打破并列。24 个状态的实质 payload regret 都是 0。D1 上，这个 tie-break 相对最小 ID 平均多得到 533,979.13 bit 紧急服务。它解释了 D1 里绝大多数 ID 变化。

### Payload-constrained urgency

只在 payload 损失不超过外部预算 `delta_payload_max` 的候选里最大化紧急服务。预算不是本阶段的输出。下面的数字只说明抽样前沿上观察到的台阶，不能反向选成阈值。

- 预算为 0，也就是只允许 1 bit 并列：24 个状态中的 21 个已经到达抽样紧急最优。
- 322000 t=15：付出 93,388.79 bit 可以选到 6465，但加权和不会选它；付出 99,002.36 bit 才能选到紧急最优 5317。
- 322002 t=15：付出 67,008.16 bit 才能选到 9941。
- 322015 t=30：付出 1,601,019.99 bit 才能选到 8311。

这三个代价不是同一个预算，也不能用去掉 322015 之后的平均值来代替。

### Weighted-sum

`utility = payload_term + lambda_H * urgent_service_term`。抽样凸链给出的区间是：

- `[0, 1.213)`：全部 24 个状态保持 Payload-first。
- `[1.213, 8.653)`：只有 322000 t=15 离开 Payload-first。
- `[8.653, 10.545)`：322002 t=15 也离开。
- `[10.545, +∞)`：322015 t=30 也离开。

没有选定其中任何一个 lambda。大于 10.545 的权重会同时接受上述三笔实质损失，包括 322002 那个很差的交换。小于 1.213 的权重则只得到并列组内的紧急服务，不需要一笔 payload 预算。

## 8. 覆盖范围

抽样前沿不能外推到每个状态未评分的 13,199 个候选。池外候选仍可能支配当前前沿。t=0 只有 D0 的 4 个场景，t=15 也只有这 4 个场景；D1 没有 t=0 或 t=15。标签 CSV 的舍入使小于 1 bit 的尘埃差显示为 0，实质结论使用 1 bit 容差。没有缺失的 payload、紧急服务或候选分配字段。

成对交换点密集，但 top-1 凸链很短，所以 Gate 不是 `HIGHLEVEL_UTILITY_RULE_INCONCLUSIVE`。输入、单位和 D1 摘要能够对上，也不需要读取 validation 或 reserved test，所以不是 `HIGHLEVEL_UTILITY_RULE_BLOCKED`。

## 9. 停止

大部分已经看到的紧急服务增益可以在 payload 的 1 bit 并列中获得。后续如果还要检验规则，优先检验 Payload-first 加紧急服务 tie-break，而不是直接训练 weighted-sum 模型。

若要把 322000 t=15、322002 t=15 或 322015 t=30 的额外紧急服务也拿进来，就必须牺牲实质 payload。在研究负责人给出可接受的 `delta_payload_max` 之前，`lambda_H` 保持未定。

三个决策时刻的交换关系不一致，本阶段不建立全局 `lambda_H`。分时刻或分任务的目标也没有在这里实现。

本阶段结束后不训练 HGNN，不构建完整高层紧急度数据集，不修改正式系统。
