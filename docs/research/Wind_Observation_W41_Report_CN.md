# W4.1：240 秒的回传是因为报文把末端电量抬过了 4000 J

2026-11-15 复用 W4 的逆风种子 1103。两条报文臂在 240 秒以前的动作相同。这一拍 1 号机不发送时请求返航，及时报文时请求回传，守卫都没有改写。排序用的仍是 W3 报价。默认调度没有改。

报文没有在两个都已准入的动作之间改名次，也没有触发回退。没有报文时，回传的 0.95 分位末端电量是 3911.725 J，低于 4000 J，不能进入排序；当时只有返航准入，它又和原调度动作相同，所以记录写成 `tie_scheduler`。有报文时，同一回传报价的末端电量升到 5227.488 J，回传带着 70000 bit 的分数 6.963 被选中。原调度在这一拍仍然请求返航。

这 5202.704 J 可以逐段对上，未解释差额低于 10^-9 J。它是不发送且返航的整条轨迹，相对有报文且回传的整条轨迹。在已经收到报文的同一快照上，把首动作改回返航并不能省下这 5202.704 J。

## 240 秒的两个状态

两机位置、速度、缓存和能耗信念一致。0 号机在 (147.075 m, 899.239 m)，1 号机在 (145.508 m, 1250.432 m)，速度都是 0，仍在空中。上一拍两机分别执行 service:0 和 service:2。0 号机缓存是 0 号、1 号浮标的四个包，1 号机缓存是 2 号浮标 20000 bit 和 3 号浮标 50000 bit。3 号浮标两包都还没到岸。

电量只差已经扣过的报文：0 号机少 0.007593 J，1 号机少 0.002793 J，合计 0.010386 J。信念均值是 0.982979 和 1.240014，0.95 分位是 1.003100 和 1.260126。及时组的信息集里有 30 秒采到的风，不发送组没有。

## 四个首动作

四个回放都从及时组的 240 秒快照出发，所以都带上了已经扣掉的 0.010386 J。只指定 1 号机这一拍的请求。0 号机和之后的闭环仍用 W4 的规则。指定回传或回传之后，实际执行都没有被守卫改写。0 号机四次都执行回传。3 号浮标两包都由 1 号机送到岸上。

有报文且回传的这一格与 W4 及时组终点一致。无报文且返航比 W4 不发送组的 113807.099 J 高 0.010386 J，就是快照里已经支付的报文。原调度的 111310.329 J 仍单列，不进入这张表。

有报文时，回传比返航少用 212.468 J，净效用高 0.000590，两包却晚约 52.6 秒。无报文时，回传比返航多用 5202.694 J，两包晚 22.613 秒。报价把回传排在返航前面，和同一信息下的全队能耗、净效用一致；它没有比较到岸时间。

## 5202.704 J 和 22.613 秒

及时组减不发送组，按航段：

| 段 | 1 号机及时组 | 1 号机不发送组 | 差额 J |
| --- | --- | --- | ---: |
| 240 秒以前的报文 | 已发送 | 未发送 | 0.010386 |
| 240–270 秒 | 回传 | 返航 | −605.447 |
| 270–300 秒 | 返航 | 返航 | 5107.636 |
| 300–330 秒 | 返航 | 回传 | 699.492 |
| 330–360 秒 | 回传 | 返航 | 1.013 |

0 号机各段差额是 0。合计 5202.704 J。240 秒这一拍的回传本身比返航少耗 605.447 J；多出来的电量发生在随后补飞的返航。两包的 22.613 秒是 336.258 减 313.645，送达者都是 1 号机。报价写的 253.645 秒比实际早 82.613 秒，因为报价里另一架飞机在等待，实际 0 号机也在回传。这个到岸时刻没有进入分数，两包仍然按时，所以没有改写 70000 bit。

## 结论

该改的位置在准入用的末端电量，不在动作分数的次序，也不在守卫或回退。没有报文时报价把回传挡在 4000 J 下面 88.275 J；报文把它抬到线上 1227.488 J。单个种子里，同一信息下的回放并没有显示回传更费电。5202.704 J 只在拿掉后续报文、并且首动作改成返航时出现。到岸时间的报价偏差没有改变按时 bit。本轮不据此修改备用阈值、风权或报文时限，也不改默认调度。
