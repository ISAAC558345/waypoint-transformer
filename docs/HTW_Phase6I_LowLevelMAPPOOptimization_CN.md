# Phase-6I-K：低层 Residual MAPPO 轨迹规划优化

本阶段没有改高层方案 C、G1_RATE k=6、环境动力学、队列计账、TaskOption 或 SafetyProjector 的安全边界。冻结的 `phase6g_seed0.pt` 仍是 `92aa68785c898415439ad8c6480427593e10c851e3d392ee3a8110f3a58dbd0e`，训练前后哈希一致。没有读取 322064–322079。

新结果在 `results/phase6ik_lowlevel_opt/`。正式规划器仍加载 Phase-6G 的 actor。本轮三个新权重都没有被选为候选。

## 1. 核查

冻结 actor 在训练场景 321000–321003 上的确定性滚动给出这些量：

| 量 | 数值 |
| --- | --- |
| 通信速率特征的平均绝对值 | 219009 bit/s |
| 到目标的相对位置平均绝对值 | 6.76 m |
| 第一层对速率通道的平均绝对贡献 | 16717 |
| 第一层对任务通道的平均绝对贡献 | 2.32 |
| 第一层输出的平均绝对值 | 3.72 |
| 除以物理尺度后的第一层输出 | 0.26 |
| `tanh` 饱和比例 | 0 |
| 每步 `served_bits / 1e6` | 1.224 |
| 投影惩罚 | 3.4e-5 |
| 残差惩罚 | 5.3e-5 |
| 投影触发率 | 0.172 |
| 服务半径内的步比例 | 0.822 |

观测里已经有相对位置、距离、队列、停留计时器、剩余 hold、SINR、速率、干扰和邻近无人机。没有再加一列重复特征。问题是尺度：速率约为带宽量级，位置是米，第一层的实际输出平均绝对值是 3.72，`tanh` 在这里的导数已经很小。邻近无人机和剩余距离因此几乎推不动隐藏层。

奖励函数本身没有把交付信号淹没。在这组滚动里，投影惩罚和残差惩罚比每步交付小四个数量级。动作头也没有饱和，`log_std` 约为 -2.06。

网络仍是 2 维残差：`clip(fly_toward + 0.25 * tanh(pre))`，再进入原来的 SafetyProjector。动作维度、Actor 宽度和 Critic 宽度都没有变。新训练从 `phase6g_seed0.pt` 加载全部 Actor 权重，Critic 按原实现重新初始化。

方案 C 闭环上的投影触发率是另一回事。开发验证集上，冻结 MAPPO 的投影触发率是 0.509。随机 G1_RATE k=5 训练滚动只有大约 0.17–0.28。低层训练看到的分配和正式高层给出的分配不是同一分布。

## 2. 这一轮只改输入尺度

奖励、动作维、安全距离和服务包络都保持 Phase-6G 的实现。`low_level_reward` 仍是：

```text
served_bits / 1e6 - 0.05 * 投影均方 - 0.01 * 残差均方
```

训练时把已有特征除以环境自身的物理单位，不增加维度：

- 位置和距离：区域宽 160 m、高 80 m、对角线 178.885 m
- 队列：容量 4 block
- 速率：带宽 1e6 Hz
- SINR 和干扰噪声比：近距离无干扰 SINR，即 `tx_power / noise_power = 1000`
- 干扰：`tx_power`

这些数没有在 payload 上拟合。邻接编码器和第一层在保存前把同一组尺度折进权重，因此评估时仍然吃原始观测，`_actor_move` 不用改。折进之后的前向和“先除尺度再走原网络”在单元测试里对齐到 `1e-5`。

没有做势函数。奖励项没有增加，所以本轮没有奖励消融。消融是三条执行路径：冻结 MAPPO、只折尺度不训练、折尺度后再训练。

## 3. 训练

- 初始化：`phase6g_seed0.pt` 的 Actor
- 场景：321000–321095，不进入梯度的开发验证集是 321096–321127
- 分配：仍是均匀抽取的 G1_RATE k=5，hold=15
- PPO：`gamma=0.99`，`gae_lambda=0.95`，rollout 48，4 个环境，学习率 `3e-4`，梯度裁剪 0.5
- 预算：3 个种子，各 80 次更新
- 曲线：`results/phase6ik_lowlevel_opt/training_curve.csv` 和 `training_curve.png`

训练是稳定的。三个种子结束时 critic 的 explained variance 都在 0.91 以上，`tanh` 饱和比例保持为 0，梯度范数从最高约 69 降到约 8–11。每步交付比特在大约 1.0e6–1.4e6 之间波动，后 40 次更新没有持续上升。训练过程中的安全违反率接近 0。

## 4. 开发验证

高层是方案 C Epoch 1，候选是 G1_RATE k=6，episode 48 步。32 个场景全部跑完，没有计账中断。配对差是新策略减冻结 MAPPO，单位是 bit。Bootstrap 10000 次，种子 0，区间是 2.5% 和 97.5%。

冻结 MAPPO 的平均 payload 是 69190346.279 bit。平均首次进入服务半径 3.323 步，平均有效服务步 212.156，平均路径 6126.391 m，平均 SINR 0.332，平均干扰 0.0683，投影触发率 0.509，安全违反率 0.000651。

| 对照 | 平均差 | 95% 区间 | 正 / 平 / 负 | 平均 payload |
| --- | --- | --- | --- | --- |
| 只折尺度，不训练 | -4787732.119 | [-6037969.563, -3554531.182] | 3 / 0 / 29 | 64402614.160 |
| seed 0，80 次更新 | -2014331.441 | [-3979772.685, 93913.440] | 10 / 0 / 22 | 67176014.838 |
| seed 1 | -8009121.008 | [-9056080.483, -6897257.992] | 1 / 0 / 31 | 61181225.271 |
| seed 2 | -4229812.817 | [-5576616.995, -2728324.710] | 5 / 0 / 27 | 64960533.462 |

seed 0 的区间上沿只到 +93913 bit，下沿是 -3.98e6 bit，10 个场景变好、22 个变差。另外两个种子的区间整体为负。

其他指标也没有形成稳定改进：

- seed 0 的进入时间从 3.323 步变成 3.721 步，服务步从 212.16 变成 210.97，投影触发率 0.522，安全违反率升到 0.00326。
- seed 1 的服务步升到 227.63，投影触发率降到 0.335，但 SINR 从 0.332 降到 0.225，payload 少了约 8.01e6 bit。服务步数上升和交付下降同时出现。
- seed 2 的进入时间略短到 3.163 步，安全违反率为 0，但投影触发率升到 0.680，payload 仍然更低。

只折尺度、不训练已经平均少 4.79e6 bit。80 次更新只把 seed 0 从这条更差的起点拉回一部分，没有回到冻结策略。

## 6. 下一步

下一轮不要从这三份权重继续训，也不要同时再改奖励。冻结 MAPPO 在方案 C 上的进入时间已经大约 3.3 步，到达本身不是这组验证里的主要缺口。

这一轮说明两件事。把第一层拉回 `tanh` 的敏感区会改变已经学会的残差，短训练补不回方案 C 的 payload。训练滚动上的每步交付可以保持，同时方案 C 的完整 episode 交付下降。下一轮只改一件事：仍从 `phase6g_seed0.pt` 出发，观测和奖励都不变，把训练时的随机 G1_RATE k=5 换成冻结方案 C 在训练集上给出的 TaskOption，让残差学习它真正要执行的分配。
