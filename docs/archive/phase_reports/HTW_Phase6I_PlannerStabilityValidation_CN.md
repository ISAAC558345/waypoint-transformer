# Phase-6I-AB：正式 Planner 有限规模稳定性验证

Gate 为 **PLANNER_STABILITY_GAIN_SUPPORTED**。16 个验证场景的完整 episode 都完成了，计账没有失败。方案 C 相对 `G1_RATE k=6` 的平均配对差是 +2,644,990.809 bit，95% 置信区间是 [180,100.077, 5,016,616.161]，下界大于 0。11 个场景为正，5 个为负。

这 16 个场景已经参与过模型开发和选择。区间说明的是当前正式链路在这个验证集上的完整 episode 差异，不是独立测试集证据，也不是部署结果。

`planner_ready = True`

`deployment_verified = False`

正式配置 `phase6iaa_formal_planner/active_policy.json` 仍是 `scheme_c`、`G1_RATE`、k = 6。实验使用了两份独立副本，没有改这份正式文件，也没有回滚。Phase-6I-Z 的 15 步窗口结论仍是 **CLOSED_LOOP_GAIN_INCONCLUSIVE**，那份报告没有被覆盖。没有训练，没有读取 reserved test `322064–322079`。

## 1. 调用链与 checkpoint

两条轨迹都调用 `run_active_episode`。策略来自实验副本，不来回改正式配置。

1. `frozen_candidate_keys` 生成 `G1_RATE k=6` 候选，并按冻结字典序绑定评分下标。历史 Phase-6F 的 k=5 没有被使用。
2. 方案 C 副本加载 Epoch 1，对整个候选池评分，同分保留更小的下标。基线副本对同一构造规则做速率加和，不调用方案 C。
3. `make_option` 保持 hold = 15。决策时刻是 0、15、30、45。
4. 同一个冻结 MAPPO-V2 用确定性均值通过原有 `SafetyProjector`，再执行 `env.step`。

两边各自 `reset(seed=scenario_id)`，torch 种子都是 `1000000 + scenario_id`。每个场景只有这一对种子，所以场景级统计就是这一条配对差。16 个场景在 reset 之后的环境随机数状态相同，episode 结束时也没有消耗环境随机数。MAPPO 没有对动作分布抽样。这次环境随机数是严格配对的。

审计前后哈希没有变化。

## 4. SINR、干扰、服务与耗时

方案 C 的平均 SINR 在多数场景更高，但 322055、322057、322062 不是。322048 的方案 C 平均 SINR 是 0.473，基线是 0.283，payload 却更低。322062 的方案 C 平均 SINR 是 0.325，基线是 0.337，payload 却高出约 9.30e6 bit。平均 SINR 不能单独解释配对差。

干扰均值大约在 0.034 到 0.128。平均速率大约在 2.18e5 到 3.04e5 bit/s。方案 C 平均每架 UAV 的有效服务步数大约是 32 到 37 步，基线大约是 36 到 38 步。服务步数更多的一侧不一定交付更多。逐 UAV 的服务步数在 `phase6iab_planner_stability/summary.json`。

方案 C 在 16 个场景的全部决策里都没有 idle。基线有 7 个场景各出现 1 个 idle 槽位。目标变化只出现在 hold 到期后的新决策；执行中途没有改写 TaskOption。非法 assignment 是 0。SafetyProjector 干预大约是每段 episode 20 到 32 步。

方案 C 的 episode 平均耗时 1.929 秒，其中高层 0.956 秒。基线平均 2.178 秒，其中高层 0.928 秒。32 段 episode 的异常数是 0。

## 5. 计账、异常与回滚

每一段的 payload 与 `served_bits` 之和一致，守恒误差没有超过容差，终止时刻都是 48。t=0 的两边候选池哈希在 16 个场景上都相同。没有 NaN/Inf，没有非法 assignment，因此没有把正式策略改成 `g1_rate`。

回滚方法没有被使用。若以后需要，把正式配置里的 `high_level_policy` 改成 `"g1_rate"` 即可；实验副本位于 `phase6iab_planner_stability/config_scheme_c.json` 和 `config_g1_rate.json`。
