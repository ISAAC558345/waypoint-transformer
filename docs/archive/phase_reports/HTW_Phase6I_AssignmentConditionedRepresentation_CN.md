# Phase-6I-S：Assignment-Conditioned 候选表示原型

Gate：`ASSIGNMENT_CONDITIONED_REPRESENTATION_INCONCLUSIVE`

本阶段冻结 Phase-6I-D 的 Epoch 6 编码器，只新训练一个候选条件化评分头。没有重训 MAPPO，没有改候选生成器，没有接入 planner，没有覆盖已有 checkpoint，也没有读取 reserved test `322064–322079`。四个旧 checkpoint 的 SHA-256 在运行前后一致。

判定在训练前写定。表示检查失败、基线 Top-1 对不上已发表计数，或 checkpoint 哈希改变，记为 `ASSIGNMENT_CONDITIONED_REPRESENTATION_BLOCKED`。两颗种子都要同时满足：总体 Top-1 和 `t=15` Top-1 都严格高于 Epoch 6 与方案 C；相对这两个基线的 scenario 整组重抽样均值区间下界大于 0，`t=15` 的均值区间也要如此；48 个状态的配对中位数大于 1 bit；至少 12 个 scenario 的三时刻合计为正，且正的 scenario 多于负的 scenario。只看平均 J15 上升不算支持。有一颗种子不满足，就记为 `ASSIGNMENT_CONDITIONED_REPRESENTATION_INCONCLUSIVE`。

表示检查和基线复核都通过了。两颗种子的决策结果都没有达到上面的支持线。

## 1. 现有架构和候选信息在哪里丢失

评分链路是冻结的 `JointUtilityHGNN.condition` 加上 `JointAssignmentDecoder("matching")`。一个决策状态的张量是：

| 张量 | 形状 | 含义 |
| --- | --- | --- |
| `uav` | `[1, 6, 8]` | UAV 位置、速度、当前进度、当前关联 |
| `buoy` | `[1, 12, 8]` | 浮标位置、队列、占用和到达 |
| `edge` | `[1, 6, 12, 3]`，送入编码器前补成 4 维 | 全部 UAV–浮标边的距离、假设速率、步数，再加队列 |
| `edge_uu` | `[1, 6, 6, 2]` | UAV 间距，以及当前关联上的干扰 |
| `global` | `[1, 3]` | 时刻、总队列、UAV 数量 |
| `assignment` | `[13327, 6]` | 候选。idle 为 `-1` |

编码器宽度是 128。节点和边先各自过 MLP，再做两层 UAV–浮标消息传递。每个 UAV 收到的是它指向全部 12 个浮标的消息均值，每个浮标收到的是全部 6 架 UAV 的消息均值。这个均值不看当前候选选了哪条边。UAV–UAV 边用的是到达决策时刻时的关联；`t=15` 上候选链路还不在服务半径内，所以这条边不随候选配对变化。`condition` 再把全体 UAV、被占用浮标和 global 做一次均值，加到每一个节点上。这个平移对 13,327 个候选完全相同。

完整 assignment 第一次进入模型，是在 `score_assignments`。它取出所选 UAV–浮标 pair logit，再求和。idle 贡献 0。因此分数是六条边的可加和，没有“这六条边同时被选中”的交互项。同一浮标集合里的两种配对，只有 pair logit 不同才会得到不同分数。边的差异在进评分头之前已经被对所有浮标的均值冲淡。

Epoch 6 的 696,320 个编码参数，包括节点 MLP、边 MLP、消息层和 `mix`、`u_proj`、`b_proj`，都可以按原形状加载。匹配 decoder 的 33,025 个参数继续冻结，不进入新评分头。没有改任何旧权重的维度，也没有往旧 checkpoint 里加 adapter。

## 2. 新表示

新评分头只在所选的六条边上取编码器状态，再拼上决策时刻就能算的 12 列。J15、`utility_rank`、未来 SINR、MAPPO rollout、直线 15 步比特和运动学比特都不进入。hold 固定为 15，所有候选相同，所以不单列。几何干扰用的是当前位置上的路径损耗和 κ，不是执行后测到的干扰。

每一列的形状都是 `[13327, 6]`，按 UAV 排列：

| 列 | 来源 |
| --- | --- |
| `rel_x`、`rel_y` | 当前 UAV 坐标到目标浮标坐标，除以区域宽高 |
| `distance_norm`、`steps_norm`、`in_range` | 当前距离、进入半径所需步数、是否已在 16 m 内 |
| `hypothetical_rate_norm` | 状态里已有的假设速率，按参考速率缩放到与旧边特征相同的范围 |
| `switch`、`abandoned_progress` | 相对当前关联是否换目标，以及被放弃的服务进度 |
| `queue_fraction` | 目标浮标的当前队列比例 |
| `log_interference`、`same_cluster_fraction` | 该候选下、当前几何上的逐 UAV 干扰和同簇竞争比例 |
| `idle` | 该 UAV 是否空闲 |

边嵌入由冻结的 `edge_enc` 从 4 维边再算一次，形状 `[6, 12, 128]`，权重不更新。每个候选的 token 是 `[6, 396]`：128 维 UAV、128 维被选浮标、128 维被选边、12 维原始列。空闲 UAV 的浮标、边和原始列置零，只保留 idle 标志。评分头对六个 token 做共享 MLP，得到 64 维，再把求和与最大值拼成 128 维，映射成一个标量。UAV 编号同时置换时，求和与最大值不变。

`322051` 的 t=15 上，方案 C 与交换 UAV 1、UAV 2 之后，被交换两架 UAV 的边嵌入平均绝对差是 0.0325。没有换目标的 UAV，其编码器状态最大绝对差是 0。同一 assignment 重复前向的分数差是 0。置换 UAV 轴后的分数差是 `2.38e-7`，原始特征差是 0。

## 3. 参数和检查

新模块随机初始化，共 37,889 个参数。优化器里只有这些参数。编码器 `requires_grad` 全是假。训练损失与 Epoch 6 相同，是 `j15_i > j15_j` 的配对上 `mean(-logsigmoid(s_i - s_j))`，按 1,024 行分块。标签只决定配对方向。

训练集是 `322000–322047` 的 t=0、15、30，共 144 个状态。验证集是 `322048–322063` 的同样三个时刻，共 48 个状态。同一 scenario 的三个时刻留在同一个划分。学习率 `3e-4`，权重衰减 `1e-4`，梯度裁剪 1.0，轮数 3，种子 0 和 1。设备是 CPU。每个 epoch 约 354–360 秒。第 1 轮的梯度最大值是 5.68 和 5.86，触发了裁剪，数值有限，没有 NaN。

`322000` t=15 的一次反向传播中，评分头梯度有限且非零，损失是 0.676。初始化不同的两个评分头，在同一状态上的平均绝对分数差是 0.532。候选行与 J15 行数都是 13,327。重新打分后，Epoch 6 的所选下标与 `best_states.json` 全部一致，方案 C 与 `epoch_001_states.json` 全部一致，Top-1 仍是 27/48 和 32/48。

## 4. 同口径验证对照

三个模型使用同一 13,327 候选池和同一 `j15_bits`。Top-1、Top-3、Top-5 命中 1 bit 最优组。normalized regret 是 `(最大 J15 - 所选 J15) / (最大 J15 + 1)`。排序是稳定的按分数降序。scenario 区间把一个 scenario 的三个时刻绑在一起，重抽样 10,000 次，种子 0。新评分头的 epoch 在验证平均 J15、Top-1、更低 regret、更低训练损失这个顺序下选择。两颗种子都选了第 3 轮。这个选择用的就是下面这 48 个状态，不是 reserved test 上的确认。

| 模型 | Top-1 | Top-3 | Top-5 | regret | 平均 J15 | 中位 J15 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Epoch 6 | 0.5625（27/48） | 0.6250 | 0.6667 | 0.0507 | 18,892,120 | 19,955,513 |
| 方案 C Epoch 1 | 0.6667（32/48） | 0.7083 | 0.7083 | 0.0355 | 19,240,091 | 20,307,051 |
| 新评分头，种子 0 第 3 轮 | 0.6667（32/48） | 0.7500 | 0.7917 | 0.0390 | 19,162,006 | 19,962,179 |
| 新评分头，种子 1 第 3 轮 | 0.5833（28/48） | 0.6667 | 0.7083 | 0.0446 | 19,028,783 | 19,997,407 |

种子 0 的总体 Top-1 与方案 C 相同，没有更高。种子 1 的总体 Top-1 只比 Epoch 6 多 1 个状态，低于方案 C。两颗种子相对 Epoch 6 的均值区间分别是 [-110,573, 639,828] 和 [-268,455, 562,536]，都跨过 0。中位数分别是 0 附近的浮点尘埃和 0。相对方案 C，种子 0 的平均差是 -78,086 bit，区间 [-589,246, 377,557]；种子 1 的平均差是 -211,309 bit，区间 [-664,608, 215,779]。scenario 方向也不齐：种子 0 相对 Epoch 6 是 10 正 6 负，相对方案 C 是 9 正 7 负。

`t=0` 上四个结果都是 16/16 命中，regret 为 0。差别在 `t=15` 和 `t=30`。

| 模型 | t=15 Top-1 | t=15 Top-5 | t=15 平均 J15 | t=15 最优组中位排名 | t=30 Top-1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Epoch 6 | 0/16 | 2/16 | 20,969,733 | 61.5 | 11/16 |
| 方案 C | 2/16 | 2/16 | 21,465,607 | 132 | 14/16 |
| 种子 0 | 4/16 | 7/16 | 21,502,046 | 41 | 12/16 |
| 种子 1 | 1/16 | 4/16 | 21,139,752 | 47.5 | 11/16 |

种子 0 在 `t=15` 把 Top-1 从方案 C 的 2/16 提高到 4/16，Top-5 提高到 7/16，最优组中位排名从 132 移到 41。这不是两颗种子的共同结果。种子 1 的 `t=15` Top-1 是 1/16，低于方案 C。种子 0 的 `t=15` 相对方案 C 的均值区间是 [-1,212,318, 1,203,943]，相对 Epoch 6 是 [-574,941, 1,505,643]，两边都跨过 0。`t=15` 的 Top-1 与 Top-2 分数差中位数，种子 0 是 `1.43e-6`，种子 1 是 `2.15e-6`。高收益候选的分数仍然叠在一起。

精确浮点最大行的名次，本次按 `j15_bits` 的第一个最大值计。这个定义下，`t=15` 的中位名次是 Epoch 6 为 190，方案 C 为 285.5，种子 0 为 280.5，种子 1 为 254.5。种子 0 的最优组更靠前，精确最大行仍远在 Top-5 之外。

推理计时从状态已经载入内存之后开始，不含候选生成，也不调用 MAPPO。匹配 decoder 的前向中位数是 0.006 秒。新评分头的一次冷前向包含冻结编码、12 列原始特征和评分头，中位数是 0.280 秒，最大 0.365 秒，48 个验证状态合计 14.0 秒。进程工作集约 2.8 GiB，其中含有 192 个状态的编码缓存，不是单个状态的增量显存。本机没有使用 CUDA。

## 5. 是否继续训练

不进入下一阶段训练，也不解冻编码层。

表示接口本身是通的：交换配对会改变对应的边嵌入，相同 assignment 的分数一致，UAV 置换不改变分数，梯度有限。决策结果没有跟着稳定下来。种子 0 的 `t=15` Top-5 有提高，种子 1 的总体 Top-1 低于方案 C，所有预先登记的均值区间都跨过 0，中位配对差仍是 0。现有证据不能把种子 0 单独留下来。

编码层已经提供了节点和边的 128 维状态。新评分头还额外看到了逐候选的几何和干扰列。继续更新那 696,320 个编码参数，并不能从这次两颗种子的分裂里推出稳定的 Top-1 增益。

## 6. 停止条件

本阶段在此停止。新评分头只写在 `phase6is_assignment_conditioned/seed_0/head.pt` 和 `seed_1/head.pt`。冻结编码器、Epoch 6、方案 C Epoch 1 和匹配 decoder 的文件没有改写。不接入 planner，不重训 MAPPO，不再增加训练轮次。
