# Phase-6I-L：低层动作机制与轨迹规划能力优化

正式低层仍然是冻结的 `phase6g_seed0.pt`，SHA-256 为 `92aa68785c898415439ad8c6480427593e10c851e3d392ee3a8110f3a58dbd0e`。Phase-6I-K 的三份权重没有被加载，也没有写回原 checkpoint。高层方案 C、G1_RATE k=6、hold=15、环境动力学、队列计账、TaskOption 和 SafetyProjector 的安全边界都没有改。没有读取 322064–322079。

Gate：

- `ACTION_MECHANISM_AUDIT_COMPLETE`
- `DIRECT_ACTION_SMOKE_PASS`
- `LOW_LEVEL_ACTION_GAIN_INCONCLUSIVE`

三个直接速度策略的配对区间都整体为负，所以没有达到收益验收，不能替换正式低层。

## 1. 残差动作的可达范围

`fly_toward` 对每个已分配无人机输出指向目标浮标的单位向量，空闲或已经重合时输出 0。单位向量经过环境步长 22 m，就是沿目标方向走满一步。它不包含减速。

冻结执行是：

```text
command = clip(fly_toward + 0.25 * tanh(actor_mean))
```

`tanh` 把每个分量限制在 (-1, 1)，再乘 0.25，残差的每个轴最多 0.25 个单位步。与单位目标向量相加并截断到长度 1 之后，可达集合是：

| 量 | 数值 |
| --- | --- |
| 相对目标方向的最大偏角 | 18.435 度 |
| 沿目标方向的最低速度 | 0.75，即 16.5 m/步 |
| 最大偏角时的速度 | 0.791 |
| 能否悬停 | 否 |
| 能否反向 | 否 |
| 最大位移 | 22 m |

这是几何上界，不是训练曲线。确定性测试确认了偏角上界、直接速度的四个方向、非有限输入变成悬停、+x/+y 与环境坐标轴一致、位移不超过 22 m、assignment 不被动作改写、过近无人机被推开，以及服务包络把外冲动作拉回内半径 15.5 m。5 个测试通过。

冻结 actor 在 321000 和 321001 上的实际输出比这个上界更窄。333 个有目标的无人机步里，命令速度平均 0.982，残差长度平均 0.077，相对 `fly_toward` 的平均偏角 2.66 度，最大 6.23 度。半径内和半径外都是这个量级。投影对这条 G1_RATE 滚动的平均修正量是 0.018。当前权重并没有顶到 18 度的边界，它选择紧贴直线趋近。

方案 C 开发验证上的投影触发率是另一回事：冻结 MAPPO 为 0.509。训练时看到的随机 G1_RATE k=5 和正式高层的 k=6 分配不是同一分布。

推理只严格恢复 Actor。checkpoint 里有 Critic，但执行不用 Critic，也不恢复优化器。Phase-6G 的训练入口从旧的 `mappo_original.pt` 热启动，不会从 `phase6g_seed0.pt` 续训。Phase-6G 的观测没有归一化。

因此，动作幅度是结构上的限制，但不是这份冻结权重在 G1 滚动里用尽的限制。观测尺度和训练分配覆盖是另外两个已经看到的因素。只把动作空间放大，并不能自动变成更好的轨迹。

## 2. 直接速度命令

新模块在 `src/wt/benchmark_v2/phase6il_direct_action/action.py`。Actor 的二维输出经 `tanh` 后截断到单位步，作为世界坐标速度：+x、+y 与环境位移轴一致，长度 1 对应 22 m，0 是悬停。目标仍然只来自 TaskOption。hold 内每步都可以改速度和方向。

旧残差权重不能解释成这个速度，所以没有加载 `phase6g_seed0.pt` 或 Phase-6I-K。网络结构仍是原来的 `ResidualActor`，独立初始化。训练前用 80 个 epoch 把 `tanh(mu)` 拟合到 `0.9 * fly_toward`，只作为初始方向，之后 PPO 不再加这项损失。三个种子的拟合余弦是 0.876、0.914、0.883。

奖励仍调用 Phase-6G 的 `low_level_reward`。交付项是 `served_bits / 1e6`，投影项系数 0.05。原来的 0.01 残差项现在作用在整条速度命令上，因为直接动作没有单独的小残差。系数没有新加，但这一项从此惩罚全速运动。输入使用与 Phase-6I-K 相同的物理单位尺度，并在保存时折进第一层，评估仍吃原始观测。

训练场景 321000–321095，评估场景 321096–321127。PPO 与 Phase-6G 相同：`gamma=0.99`，`gae_lambda=0.95`，rollout 48，4 个环境，各 80 次更新。

训练结束时三个种子的 explained variance 分别为 0.937、0.926、0.917，critic loss 在 4–6 附近。训练每步交付仍在大约 1.0e6–1.2e6 bit。这个训练奖励没有对应更高的方案 C payload。

平均修正量分别是 0.246、0.463、0.656。服务步分别是 192.719、167.688、147.625，都低于冻结策略的 212.156。32 个场景都完整，计账没有中断。

Phase-6I-K 的尺度微调也没有超过冻结策略，平均差分别是 -2014331.441、 -8009121.008、 -4229812.817。直接速度的损失比 K 更大。共同现象是训练滚动上的交付可以保持，方案 C 的完整 episode 交付下降。

直接速度的路径只有冻结策略的一半甚至六分之一，进入服务半径晚了大约 2–3 步。Actor 确实不再被 18 度上界绑住，但它把速度降了下来。服务半径内的 SafetyProjector 仍会把要离开内半径的动作拉回来，所以投影触发率升到 0.70–0.94。安全违反率没有高于冻结策略。

## 4. 瓶颈判断

当前闭环变慢，主要不是因为残差只剩 18 度。冻结权重自己只用了大约 6 度，并且几乎全速趋近。把动作改成任意方向和任意速度后，在同一套交付奖励和 0.01 命令惩罚下，策略选择更短的路径，投影更频繁，payload 下降。直线趋近的硬速度在这个奖励里承担了“按时进半径”的作用；去掉它之后，80 次更新没有学回同等的接近效率。

观测尺度和 G1 k=5 / 方案 C k=6 的分配差异仍然存在。这一轮没有把它们和动作机制一起改掉。
