# Phase-6I-Q：低层训练任务分布与方案 C 的对齐审计

本阶段没有训练，没有改 `FormalPlanner`，没有覆盖 checkpoint。正式低层仍是 `phase6g_seed0.pt`，SHA-256 为 `92aa68785c898415439ad8c6480427593e10c851e3d392ee3a8110f3a58dbd0e`，审计前后哈希一致。没有读取 322064–322079。Phase-6I-P 的日志只被读取。

Gate：

- `TASK_DISTRIBUTION_AUDIT_COMPLETE`
- `TASK_DISTRIBUTION_MISMATCH_CONFIRMED`

失配来自任务是怎么被选中的。`k=5` 和 `k=6` 这两个整数本身不能解释 15 步交付差。TaskOption、动作公式、队列更新和 15 步服务窗口是同一套接口。

## 1. 接口

训练和正式执行都调用 `make_option`。在场景 321096 的初始状态上核对：

| 项目 | 训练 | 正式执行 | 核对 |
| --- | --- | --- | --- |
| TaskOption | `association == targets` | 同一构造 | 一致 |
| 决策时剩余 hold | 15，随后每步减 1 | 15，随后每步减 1 | 序列都是 15…1 |
| 动作公式 | `0.25 * tanh(pre)` 加 `fly_toward`，再截断并投影 | 确定性均值代入同一公式 | 均值命令与 `_actor_move` 一致 |
| 采样 | 训练对 pre-tanh 高斯采样 | 评估使用均值 | 映射相同，随机性不同 |
| 队列 | `L3BBitQueueEnvV2.step` 的 `apply_service_then_arrival` | 同一函数 | 一致 |
| 服务窗口 | hold=15，决策在 0、15、30、45 | 同一窗口 | 一致 |
| 奖励尺度 | 1e6 bit 对应任务奖励 1 | 评估 payload 使用同一计账 | 一致 |

投影器配置仍是 `CollisionConfig(0.4, 0.2)` 和内半径裕量 0.5 m。审计里的反事实 15 步回放在恢复状态后，时间和队列与决策前一致；正式轨迹上的交付比特与这次回放一致。

## 2. 同一状态下的任务分布

对比固定在方案 C 实际走到的决策状态上。低层执行器都是冻结的确定性 `phase6g_seed0.pt`，所以交付差来自分配，不来自另一套控制器。15 步交付只统计 t=0、15、30 这三个完整窗口；t=45 只剩 3 步，不进入交付配对。距离、半径、队列、SINR 和干扰包含全部四个决策时刻。

开发验证 321096–321127，共 32 个场景、128 个决策。`train_k5` 是该状态上 `G1_RATE k=5` 合法池的均匀样本，静态量 32 个、15 步交付 2 个。`uniform_k6` 对 `k=6` 池做同样的均匀抽样。方案 C 是该状态上的唯一正式选择。

k=6 均匀样本减 k=5 均匀样本的 15 步交付差是 -286602.129 bit，区间 [-822710.071, 228583.867]，跨过 0。把池从 5 扩到 6 再继续均匀抽样，交付并不高于 k=5，空闲比例仍有 0.305。正式任务的高交付来自方案 C 选中的那一个满分配，不是来自池子更大。

方案 C 的目标平均远 3.2 m，SINR 更低，干扰更高，因为 6 条链路同时发射。随机 k=5 任务更稀疏，单链路 SINR 更高，但 15 步总交付少约 2.45e6 bit。队列差约 3.3%，半径内比例差 0.027，这两项没有达到预先写定的失配幅度。

训练场景抽查 321000、321016、321032、321048、321064、321080、321088、321095 给出同一结构：方案 C 的 15 步交付 21362783.405 bit，k=5 均匀样本 18497520.064 bit，空闲比例 0 对 0.348，方案 C 落在 k=5 池外的比例 0.875。开发场景和训练场景的初始几何不是这道差的来源。

P 的评估是方案 C 完整 episode。塑形只在训练回报里。开发验证上，payload 差和任务奖励差的相关系数是 1.000。塑形差和 payload 差的相关系数是 seed 0 的 0.187、seed 1 的 0.311、seed 2 的 -0.026。

## 4. 根因

接口没有分叉。剩余 hold、动作公式、计账和服务窗口一致。

分布失配成立，而且不是“k 从 5 写成 6”这一件事。训练在每个决策上均匀抽取包含大量空闲的 k=5 分配；正式系统由方案 C 选出一个 6 架 UAV 都有目标的分配，其中约 83% 根本不在 k=5 池里。同一冻结执行器下，这个正式任务每 15 步多交付约 2.45e6 bit，同时干扰更高、SINR 更低。均匀抽取 k=6 不能复现这个任务，15 步交付差的区间跨过 0。

P 的 seed 差异因此不能归因于势函数大小。塑形只占任务奖励的约 6.5%，并且和 payload 差几乎不相关。seed 0 的正号是区间跨过 0 的平均，去掉一个场景就为负。seed 1 的损失在任务奖励里，而它的训练交付曲线仍然平稳。低层是在另一类更稀疏的任务上更新的。

## 5. 唯一下一步

停止距离势函数。下一步只改训练时的任务来源：在 321000–321095 上，每个 hold 边界用冻结的方案 C 选出分配，低层仍用原始奖励 `served_bits / 1e6 - 0.05 * c_project - 0.01 * c_residual`，从 `phase6g_seed0.pt` warm-start，动作保持 `alpha=0.25` 的原始残差。评估仍在 321096–321127 上与冻结低层配对。不要把 k=5 均匀池换成 k=6 均匀池，也不要继续调塑形系数。高层权重、Planner、环境动力学和安全边界保持冻结。
