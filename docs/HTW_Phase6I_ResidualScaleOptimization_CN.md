## 1. 原始动作映射

冻结执行在 `phase6g_lowlevel_mappo/evaluate.py` 的 `_actor_move`，训练侧 `worker.py` 使用同一公式。顺序是：

```text
pre = actor_mean
delta = alpha * tanh(pre)
desired = clip_unit_step(fly_toward + delta)
executed = SafetyProjector(desired)
executed = 0            if projector failure
executed = clip_unit_step(executed)
position += executed * 22 m
```

Actor 的最后一层是 `Linear(64, 2)`，输出两个无界值。推理使用确定性均值，不采样，也不使用 Critic。`tanh` 之后每个分量落在 (-1, 1)。乘上 `alpha` 之后，它们是世界坐标里的笛卡尔残差：维度 0 加在 +x，维度 1 加在 +y。它们不是转向角，也不是速度。

`fly_toward` 对已分配无人机给出指向目标浮标的单位向量，空闲或已经重合时给出 0。单位向量再乘环境步长 22 m，就是沿目标方向走满一步。残差加到这个向量上，然后把欧氏长度截断到 1。空闲无人机的基础向量是 0，残差本身仍可形成不超过一个单位步的位移。这和 Phase-6I-M 把零目标改成悬停不同。

`alpha = 0.25` 只乘在 `tanh(pre)` 上，发生在与 `fly_toward` 相加之前，也发生在长度截断之前。每个轴的残差因此不超过 0.25 个单位步。残差盒是 `[-alpha, alpha]^2`。在这个盒内，相对目标方向的最大偏角和沿目标方向的最低速度是：

| alpha | 最大偏角 | 沿目标最低速度 | 最大偏角时的速度 | 能否悬停或反向 |
| --- | --- | --- | --- | --- |
| 0.25 | 18.435° | 0.75 | 0.791 | 否 |
| 0.35 | 28.301° | 0.65 | 0.738 | 否 |
| 0.50 | 45.000° | 0.50 | 0.707 | 否 |
| 0.75 | 71.565° | 0.25 | 0.791 | 否 |

这是几何上界。SafetyProjector 在截断后的命令上分离距离小于 1.0 m 的无人机，并把服务中的无人机拉回内半径 15.5 m，然后再限制步长和区域。投影失败或结果非有限时，这一步执行零位移。扫描没有放宽这些边界。

在场景 321096 的第一步方案 C 决策上，`alpha=0.25` 的命令和投影触发标记与正式 `_actor_move` 一致。3 个几何测试通过：缩放发生在截断之前，空闲基础向量仍保留笛卡尔残差，0.75 与 0.25 使用同一个相加顺序。

Phase-6I-M 使用了同一个二维 Actor，但把维度 1 解释成相对 `fly_toward` 的转角，把维度 2 解释成速度。那次扫描不能用来判断 0.25 这个缩放是否太小。本阶段的候选值只改变 `alpha`，动作语义保持原样。

## 2. 冻结 Actor 的幅度扫描

Actor 权重保持 `phase6g_seed0.pt`，奖励、动力学和安全边界都没有改。评估是方案 C 的完整 episode，初始状态由场景种子决定，高层和低层都是确定性的。筛选场景是开发池中的 321096、321100、321104、321108、321112、321116、321120、321124。

停止规则：平均 payload 比 0.25 低超过 1e6 bit，并且已完成场景里至多一个不是负的，就停止该缩放，不再跑剩余场景，也不再试更大的缩放。安全违反率比对照高过 0.02 时同样停止。0.35、0.50、0.75 都在前 4 个场景触发了交付下降，因此没有跑完 8 个筛选场景，也没有进入全部 32 个开发场景。

实际偏角大约是 4°、6°、8.5° 和 13.5°，都低于上表的几何上界。冻结权重没有顶到 0.25 的 18.435° 边界。把 `alpha` 从 0.25 提高到 0.75，只是把已经很小的世界坐标残差放大，实际偏角大致按比例增加，命令速度从 0.976 降到 0.939，路径缩短大约 70–200 m。

## 3. 唯一正场景

0.35 只有场景 321104 的 payload 更高，差 +2127696.407 bit。同一场景的 SINR 从 0.367 降到 0.263，干扰从 0.051 升到 0.071，有效服务步从 209 降到 203，进入时间从 2.750 步变为 3.091 步。另外三个场景的差是 -7960941.376、-3378401.900 和 -5907938.180 bit。去掉 321104 后，0.35 的平均差是 -5749093.819 bit。这个正差没有伴随更好的 SINR 或更多服务步，不能当作该缩放的依据。

0.50 和 0.75 在这 4 个场景上没有正差。

## 4. 判断

放大原始残差没有提高实际交付量。0.25 的几何上界不是这份冻结权重用尽的限制；权重实际只走出大约 4°，而执行器也确实执行了放大后的 6–14°。交付下降和投影是否更频繁没有绑定在一起。继续增大 `alpha`，或用更大的 `alpha` 从这份权重做 warm-start，都没有扫描证据。

正式执行继续使用 `alpha=0.25` 的冻结残差 MAPPO。
