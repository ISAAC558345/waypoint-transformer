# 研究优先级与必要测试规则

生效日期：2026-11-04。依据用户本次明确要求：完善原系统与新研究同步推进；冲突时先完善原系统；每次指令只执行必要测试，包括直接回答方法 A/B 优劣的对照，取消无关繁杂的安全专项和默认全套检查。

## 1 优先级

原系统的可运行、可复现和可信比较是第一优先级。新方向可并行开展独立的资料整理、问题定义和轻量核算。共享入口、依赖、模型、数据协议或算力发生冲突时，先完成影响当前工作的原系统任务。

没有依赖关系的历史锁、旧图或归档缺失不要求一次全部清零。每包解决明确问题并保留剩余事项，不能把新增失败为零当作原系统完善完成。原标签服务目标继续保留，M0 的完成不替代其验收。

## 2 测试选择

每条执行指令写清要回答的问题、改动模块、最小测试或方法对照、预算和停止条件。先复用已存结果，只有新改动、失败或未解决的不确定性需要时才补测。

| 工作 | 必要验证 |
| --- | --- |
| 文档、状态和归档 | 内容与来源核对、实际文件可读；不运行仿真 |
| 一个接口或记账修复 | 直接相关的最小回归，必要时覆盖直接调用者 |
| 比较 A/B 方法 | 同信息、同资源、同场景的对照，记录主要指标和成本 |
| 物理公式修正 | 一个可手算参考例及受影响数值比较 |
| 改到碰撞、投影或能量可行性 | 只检查实际受影响的约束行为 |

不默认运行全历史套件，不增加独立故障注入、广泛安全压力、反复哈希审计、与研究问题无关的mock边界矩阵。已有必要运行自然产生的异常、约束事件和错误记录照常保留，不为这些字段另造大量实验。

共享核心确实改变时，可增加直接相关回归，并说明它能发现什么问题；不能仅以文件涉及面大为由自动重跑所有历史轮次。失败先诊断；修复后只重跑受影响部分。不得通过删测试、忽略实际错误、放宽容差或改写旧结果制造通过。

## 3 统计与预算

小样本功能对照只报告逐场景结果与限制；不以两场景均值宣布泛化增益。正式方法优劣研究预先固定主要指标和比较条件，样本量依据开发方差与所需结论选择。无需为所有探索自动附加多种子大矩阵、bootstrap或完整新holdout。

训练、策略运行和解析核算预算在各包单独登记。测试套件内既有调用单独记录，不能借测试扩充研究样本。已知历史206项失败从已有日志分类；无新原因时不再为重复得到206这个数运行全套。

## 4 与旧指令的关系

本规则按用户最新要求，替代旧 AGENTS 和交接中“每次变化都跑完整历史套件”的一概要求，也替代无关安全专项作为每阶段前置的安排。历史报告保留原文。本规则不宣称系统已经安全、可发布或所有测试通过；实际结论只覆盖所执行的必要检查。

执行端如从旧分支开始，先读取本规则，将当前工作分支的现行执行说明同步为此规则；不需要为已经授权的测试裁剪再次向用户确认。
