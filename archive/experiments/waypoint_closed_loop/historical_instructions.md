# Round-6 Working Rules

- This is a closed-loop evaluation-only round. It must not create an optimizer, call backward, update a parameter, or create a training checkpoint.
- Round-3 data, Round-4 Waypoint checkpoints, Round-5 policy checkpoints, and the Round-5 lock are read-only provenance inputs.
- Evaluate all saved model seeds for the six specified deployable controls. Oracle-waypoint controls are diagnostic-only and excluded from formal ranking.
- Every physical scenario is represented by a deterministic snapshot and fully materialized arrival trace. Policies compared within a scenario reset from the same snapshot and use the same fixed reference goal.
- A reference goal is generated by a frozen non-learning policy before tested-policy rollout. A tested policy never reads its own future state/action or a future value from the reference trajectory.
- WT recomputes the frozen H=30 waypoint at every environment step; causal context contains only current and previous evaluated-policy observations.
- Every neural raw action uses the same radial safety projection before a single `env.step` call. Do not replay stored next states.
- Do not add PPO, HGNN, extra UAVs, buoy drift, dynamic channels, or new resource-action semantics. Stop after Round-6 is audited and locked.
