## Key bug fixes found during integration

1. Reset/step `info` distinction:
   the reset dictionary has physical state but no transition-only energy/action
   fields. Runner validation now requires transition fields only after `step`.

2. No-save K audit:
   split assignments are computed whether or not NPZ trajectories are saved,
   so `--no-save-trajectories` still performs a valid K-step audit.

3. Dynamic dimensions:
   trajectory construction resolves `state_dim` and `action_dim` from the
   observation schema, reset metadata, or explicit arguments and rejects
   conflicts. It no longer hard-codes state/action dimensions.

4. Raw-state time alignment:
   each transition now stores both pre-action raw channel state and matching
   `next_*` post-action state. Metrics and plots integrate post-action
   `next_rates_bps`, which is the step rate used by the reward. This avoids
   losing the initial raw state or shifting policy effects by one step.

5. Complete-episode validation:
   persisted episodes must end in `terminated` or `truncated`. Collector limits
   are converted to explicit truncations.

6. Full physical continuity:
   validation checks pre/next chains for observation, UAV position/velocity,
   buoy position, energy, distances, gains, SNR, per-buoy rates, and total
   rates.

7. Output preservation:
   metrics, figures, datasets, and standalone K-step CSV generation all refuse
   to overwrite existing artifacts.

8. Schema semantics:
   the final schema records identity broadcasting, observation segments,
   normalization, raw counterparts, pre/post time alignment, transition
   physics, masks, and the distinction between potential link capacity and
   actual payload.

## Baseline behavior

- `random_valid`: private seeded RNG, uniform normalized-action-ball samples;
- `nearest_buoy`: nearest current valid physical buoy, with optional current
  queue filtering if a compatible environment provides it;
- `max_queue`: masked current queue `argmax` with stable index tie-breaking;
  safely hovers because Stage 1A has no queue;
- `urgency_rate_energy`:
  `norm(U)*norm(Q)*norm(rate)/(movement_proxy+epsilon)`, omitting missing
  factors. Stage 1A supplies neither `U` nor `Q`, so the effective formula is
  current normalized rate divided by a documented one-step movement proxy.

No policy has trainable parameters, an optimizer, backward propagation, a
neural-network dependency, or access to future episode state.

## Data-flow shapes

For episode length `T`, buoy count `K_b`, environment state dimension `S`, and
action dimension `A`:

| Field | Shape |
|---|---:|
| observations / next_observations | `[T,S]` |
| actions | `[T,A]` |
| rewards / done flags / time / valid transition | `[T]` |
| valid node mask | `[T,K_b]` |
| action mask when unavailable | `[T,0]` |
| UAV raw state and next state | `[T,2]` |
| buoy positions and next positions | `[T,K_b,2]` |
| per-buoy channel state and next state | `[T,K_b]` |
| queue / actual payload when unavailable | `[T,0]` |
| desired goal under goal spec v0 | `[0]` |
| achieved goal | `[3]` |

The accepted scales have `A=2` and state dimensions `18` (`K_b=3`) and `26`
(`K_b=5`).
