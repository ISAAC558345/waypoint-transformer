## Environment semantics

The detailed pre-implementation audit is
`report/round_03_environment_semantics_audit_20260730_220254.md`.

The v1 slot order is service before arrival:

```text
D_i[t] = min(Q_i[t], C_i[t])
Q_i[t+1] = clip(Q_i[t] - D_i[t] + A_i[t], 0, Q_i,max)
drop_i[t] = max(Q_i[t] - D_i[t] + A_i[t] - Q_i,max, 0)
```

All queue, arrival, capacity, delivered-payload, and dropped-data quantities
use bit. `C_i[t]` uses the existing channel implementation. Its per-buoy rate
already includes the fixed orthogonal `1/N` bandwidth share, so the share is
not multiplied a second time.

The action remains a two-dimensional UAV motion command. There is no explicit
communication scheduling action in the accepted environment. Therefore v1
retains the existing fixed parallel orthogonal service allocation and treats a
baseline's selected buoy as its navigation target, not as a fabricated
exclusive service assignment.

Supported arrival modes are:

- `constant`;
- private-seed `poisson`;
- materialized `trace`.

The formal comparison uses materialized Poisson traces. All four policies in a
matched `(scenario_id, seed, buoy scale)` group receive the same initial UAV
and buoy state, initial queues, and complete arrival trace. Future trace
entries are never exposed to a policy.

Communication energy, urgency, deadlines, and AoI remain undefined by the
project and were not invented. The existing abstract movement/hover energy is
reported separately.

## Key fixes and root causes

1. **Missing task state.** The v0 environment exposed positions, rates, a
   capacity proxy, and abstract energy, but no queues or actual payload.
   An explicit `task_semantics_version="v1"` branch adds queue/task state while
   keeping v0 as the default compatibility path.

2. **Capacity was not payload.** Reward and metrics could not distinguish
   potential link capacity from delivered data. V1 now bounds delivered
   payload by both the pre-arrival queue and current allocated capacity, and
   uses actual delivered payload in reward and metrics.

3. **Arrival fairness.** Independent policy rollouts could otherwise receive
   different random traffic. The runner materializes one trace per matched
   case, stores its SHA-256 content ID as `arrival_trace_id`, and reuses it
   across all policies.

4. **Degenerate baselines.** `max_queue` had no queue to rank, and the old
   urgency-named rule had no real urgency. V1 supplies real queues, implements
   deterministic queue/distance/index tie-breaking, and replaces the
   misleading v1 name with `queue_rate_energy`. The legacy
   `urgency_rate_energy` name is retained only in the v0 registry for Round-2
   compatibility.

5. **Random action boundary semantics.** Sampling only from the unit ball did
   not guarantee that a step near the map edge remained physically valid.
   V1 now exposes current area bounds and maximum step distance; `random_valid`
   rejection-samples from the intersection of the unit ball and the current
   feasible motion set. The runner whitelist was updated so these current
   fields reach the policy. The canonical pilot has zero boundary projections.

6. **Unreachable preliminary goal.** An initial pilot used a residual-queue
   target of 0.02. With service-before-arrival and mean final-slot arrivals
   near 0.09 of per-buoy buffer capacity, that target was structurally
   unreachable and produced 80/80 mid-quality episodes. The canonical pilot
   uses the documented v1 residual tolerance 0.10 with completion target
   0.985. This yields both achieved-goal and suboptimal trajectories while
   preserving long `K=30` coverage.

7. **Waypoint boundary/index risk.** The builder uses
   `next_observations[t+K-1]` as the state at `t+K`, never crosses an internal
   terminated/truncated transition, never crosses an episode or split, and
   applies zero-valued masks to padded node targets. Endpoint termination or
   truncation is stored explicitly and is allowed.

8. **Figure readability.** Full episode IDs overlapped in the representative
   queue figure. Titles now use compact
   `policy | seed, buoys, T` labels. All 12 final figures were visually
   inspected.

## Data and sample shapes

### Environment v1

| Quantity | Shape |
|---|---:|
| action | `(2,)` |
| flat observation | `(9 + 7*N,)` |
| observation at `N=3` | `(30,)` |
| observation at `N=5` | `(44,)` |
| per-step node arrays | `(T, N)` |
| positions | `(T, 2)` or `(T, N, 2)` |
| desired goal | `(3,)` |
| achieved global goal | `(5,)` |
| achieved per-buoy queue/completion | `(N,)` each |

The nine global observation features are normalized UAV position and velocity,
remaining-energy ratio, remaining-horizon ratio, cumulative normalized
distance and energy, and task completion. Each buoy contributes relative
position, normalized distance, normalized current rate, normalized queue,
normalized last realized arrival, and service-completion ratio.

### Waypoint schema v1 (`N_max=5`)

| Quantity | Shape |
|---|---:|
| padded source observation | `(44,)` |
| valid node mask | `(5,)` |
| Waypoint/goal vector | `(13,)` |
| source state | `(62,)` |
| train batch | state `(16622,62)`, target `(16622,13)` |
| validation batch | state `(5419,62)`, target `(5419,13)` |
| test batch | state `(6099,62)`, target `(6099,13)` |

The 13-dimensional Waypoint vector is:

```text
[uav_x, uav_y,
 normalized_queue[0:5],
 service_completion_ratio[0:5],
 remaining_energy_ratio]
```

`waypoint_mask_t_plus_k` and `goal_mask` have the same width. Padded buoy
features have value zero and mask false. `state_t` concatenates the current
13-dimensional Waypoint view, the 44-dimensional padded v1 observation, and
the 5-dimensional valid-node mask.

Both `desired_goal` and `achieved_terminal_goal` are supported. The default
sample source is hindsight `achieved_terminal_goal`; desired and achieved
fields remain separate in stored episodes.

## Remaining limitations and future interfaces

- The environment remains single-UAV with static buoys.
- Communication energy, urgency, deadline, and AoI are still undefined.
- Communication service uses the existing fixed parallel orthogonal `1/N`
  allocation; the action controls only UAV motion.
- The pilot covers ten seeds and two buoy scales. Its readiness result is a
  bounded data-engineering judgement, not a statistical performance claim.
- The dataset has high and mid/suboptimal episodes but no low-quality class.
- Future models must consume declared schema dimensions and masks rather than
  hard-coded `state_dim`, `action_dim`, `goal_dim`, `waypoint_dim`, or node
  counts. Losses must apply `waypoint_mask_t_plus_k` before reduction.
- `run_config.base_environment_config` records the pre-override compatibility
  template and can show `task_semantics_version="v0"`; the authoritative
  `effective_case_configuration` and every stored canonical episode are v1.
- `source_dataset_manifest_sha256` is the digest of canonicalized JSON
  content, not raw file bytes.
